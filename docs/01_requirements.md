# 要件定義書

作成日: 2026-11-16
ステータス: 確定（2026-11-16）
参照: [プロジェクト計画書](00_project-plan.md)

## 1. 目的

Laravelの概念・設計判断・ベストプラクティスを、想起練習と分散学習で定着させるための自分専用の教材アプリを提供する。MVPは「教材を取り込み、受講し、復習が回る」ところまでとする。

## 2. 利用者と前提

- 利用者は自分1名。ローカル環境（`php artisan serve`）でのみ動かす。ログインはない
- 教材はClaude Codeで生成したMarkdownファイルで、`content/` に置き、コマンドで取り込む
- 1日の学習は約30分。「今日の復習 → 新しいレッスン」の順に進める
- インターネットに接続できなくても動作する（CSS・highlight.jsも `public/vendor/` に同梱する）

## 3. 用語

| 用語 | 意味 |
| --- | --- |
| 章（chapter） | レッスンのまとまり。番号とタイトルを持つ |
| レッスン（lesson） | 1ファイルの教材。固定のid（例: `ch03-l02`）を持つ |
| 事前の問い（pre-question） | 本文を読む前に予想で答える選択式の問い。採点結果は記録しない |
| 想起カード（recall card） | 頭の中で答えてから答えを開き、自己評価する問題 |
| 選択式（choice） | 選択肢から1つ選び、自動採点する問題 |
| AIコードレビュー問題（code review） | AIが書いたコードを示し、問題点を選択肢から選ぶ自動採点の問題 |
| 問題（question） | 想起カード・選択式・AIコードレビュー問題の総称。復習の対象。固定のid（例: `ch03-l02-c1`）を持つ |
| 段階（stage） | 問題ごとの復習の進み具合（1〜6）。次回の復習日までの日数を決める |
| 期限が来た問題（due） | 次回の復習日が今日以前の問題 |
| 再出題（practice） | その日に「思い出せなかった / 不正解」だった問題を、その日の最後に、正解する（`fail` 以外になる）までくり返し出すこと。結果は段階に反映しない |
| 引退（retire） | 教材ファイルから削除されたレッスン・問題を、DBから消さずに表示・出題の対象から外すこと |
| 今日 | Asia/Tokyo における、0時を区切りとした日付 |

## 4. 機能要件

| ID | 機能 | 要件 | 対応設計 |
| --- | --- | --- | --- |
| FR-01 | 教材の取り込み | `content/` 配下の章定義とレッスンファイルを読み込み、DBに追加・更新する | CMD-01 |
| FR-02 | 教材の検証 | 必須項目の欠落、形式の不正、出典URLの不正（ドメイン・バージョン不一致）、idの重複（ファイル内）・不整合がある場合、エラーを表示し、1件も取り込まない | CMD-01 / 04_content-format |
| FR-03 | 学習記録の保持 | 取り込み直しても、レッスンの完了状態・問題の段階・次回の復習日・回答履歴を変更しない | CMD-01 / 03_database |
| FR-04 | 削除された教材の扱い | ファイルから消えたレッスン・問題は引退させる。ファイルに戻れば引退を解除する | CMD-01 |
| FR-05 | ホーム | 今日の復習の残り件数と開始ボタン、次に受講するレッスン、全体の進捗を表示する | SCR-01 |
| FR-06 | カリキュラム | 章とレッスンの一覧、レッスンごとの完了状態、章ごとの進捗率を表示し、任意のレッスンを受講できる | SCR-02 |
| FR-07 | レッスン受講 | 事前の問い → 本文 → その場で思い出す → 完了 を、段階ごとの画面で進める。対象バージョンと出典を表示する | SCR-03 |
| FR-08 | 復習への登録 | レッスン完了時に、そのレッスンの問題を「段階1・次回の復習日は翌日」で登録する。登録済みの問題の状態は変更しない | SCR-03 / 05_review-logic |
| FR-09 | 復習の出題 | 期限が来た問題を1問ずつ出題する。直前と同じ章はできる範囲で避ける。期限が来た問題がなくなったら再出題を行う | SCR-04 / 05_review-logic |
| FR-10 | 復習の採点 | 想起カードは自己評価（思い出せた / あいまい / 思い出せなかった）、選択式・AIコードレビュー問題は自動採点し、正誤と解説を表示する | SCR-04 |
| FR-11 | 段階の更新 | 結果に応じて段階と次回の復習日を更新する（ルールは 05_review-logic） | 05_review-logic |
| FR-12 | 不正な送信の無視 | 期限が来ていない問題への回答、再出題の対象でない問題への練習回答、二重送信は記録せず、その旨を表示する | SCR-04 / 05_review-logic |
| FR-13 | 学習DBの保護 | 学習用DBに対して、記録を消すArtisanコマンド（`migrate:fresh` など）を実行できないようにする。DBのデータは、`docker compose down -v` で消えない場所に置く | 02_architecture |

## 5. 非機能要件

| ID | 区分 | 要件 |
| --- | --- | --- |
| NFR-01 | 環境 | PHP・Composer・Docker（DBのみ）で起動できる。Node.jsは不要 |
| NFR-02 | 画面 | Bladeのサーバーサイドレンダリングのみ。1操作1画面遷移、POST後はリダイレクト（PRG）。JavaScriptはコードのハイライトにのみ使う |
| NFR-03 | 再開性 | 復習・レッスンの途中でブラウザを閉じたり再読み込みしても、続きから正しく再開できる（出題順をセッションに保持しない） |
| NFR-04 | 型安全 | 全PHPファイルで `declare(strict_types=1)` と型宣言。Larastanはレベル max |
| NFR-05 | 品質 | Pint・Larastan・PestをGitHub Actionsで実行する |
| NFR-06 | テスト | 復習ロジックは単体テストで網羅し、時刻を固定して実行する。取り込みの検証・記録の保持・不正な送信の無視は機能テストで確認する |
| NFR-07 | 時刻 | アプリのタイムゾーンは Asia/Tokyo。DBの日時もAsia/Tokyoで保存する（ローカル専用のため、UTC変換を行わない） |
| NFR-08 | データ保護 | 学習用DBと開発用DB・テスト用DBを分ける。学習用DBのバックアップ手順を用意する |
| NFR-09 | セキュリティ | 教材の本文はHTMLをエスケープして表示する（AI生成の教材に含まれるHTMLを実行しない）。ローカル専用のためその他の対策は 02_architecture 6章 |

## 6. 計画書の論点の決定

計画書で「各設計書で確定する」とした論点を、以下のとおり決める。

| 論点 | 決定 | 理由 | 詳細 |
| --- | --- | --- | --- |
| 教材から問題が削除された場合 | 引退（`retired_at` を設定）させ、出題対象から外す。学習記録は残す | 物理削除すると回答履歴の外部キーが壊れる。誤って消した場合も戻せば記録が復活する | CMD-01 |
| 教材からレッスンが削除された場合 | レッスンと、その問題をすべて引退させる | 同上 | CMD-01 |
| 完了済みレッスンに後から問題が追加された場合 | 取り込みでは登録しない。カリキュラムに「未登録の問題あり」と表示し、レッスンを再受講して完了すると、未登録の問題だけを登録する | 取り込みで学習記録に触れないという原則を守る | SCR-02 / SCR-03 |
| 既存の問題idで種別が変わった場合 | 想起カード ⇔ 選択式はidの接頭辞（`-c` / `-q`）が違うため起こらない。`choice` ⇔ `code_review` は可 | 想起カードと選択式では結果の意味が違い、段階を引き継ぐと不整合になる | 04_content-format |
| 章のタイトル | `content/chapters.yaml` で定義する | レッスンファイルに章タイトルを重複して書かせない | 04_content-format |
| 章を避ける判定の「直前の回答」 | 今日の回答のうち最新のもの（計画書の「review_logsの最新」を今日に限定） | 前日の最後の章を翌日の最初の出題で避ける意味が薄いため | 05_review-logic |
| 再出題の回数 | 正解する（`fail` 以外の評価になる）まで、その日のうちにくり返す（計画書の「もう一度」を変更） | 間違えたままその日を終えないため | 05_review-logic |
| 選択肢の表示順 | 問題idと日付から決まる順にシャッフルする（同じ日は同じ順） | 復習を繰り返すと正解の位置を覚えてしまうため。再読み込みで順が変わらないよう、乱数ではなく決定的に並べる | 05_review-logic |
| 事前の問いを飛ばせるか | 飛ばせない（回答必須） | 事前テストの原則を守るため | SCR-03 |
| 事前の問いの回答方法 | GETのフォーム（`?answer=b`） | 記録しない＝状態を変えない操作のため、HTTPの意味としてGETが正しい。計画書の「回答はPOST」の例外とする | SCR-03 |
| DB | PostgreSQL（Docker）。計画書の SQLite から変更 | SQLiteは日付型がなく型の宣言もゆるいため、日付の比較や制約で独自の工夫が必要になる。型と制約が厳密で実務に近いDBで、Laravelの設計を学ぶ | 02_architecture / 03_database |
| 対象のLaravelバージョン | 13.x（着手時点で最新安定版を再確認する） | 計画書の方針 | 04_content-format |

## 7. 対象外

計画書 4章のフェーズ2候補と対象外（公開・デプロイ、ログイン、アプリ内からのAI API呼び出し）に加え、以下はMVPでは扱わない。

- 画面からの教材の編集・削除（教材は常にファイルが正）
- 復習の1日の上限、翌日への繰り越し
- 回答履歴の閲覧画面（review_logs は記録のみ行い、フェーズ2の学習記録で使う）
- 学習記録のエクスポート・インポート
