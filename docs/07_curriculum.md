計画書 5章のカリキュラム（案）を、レッスン単位に分解する。教材を生成するときは、この設計書の該当する章を参照する。

## 1. 方針

- 1章あたり3〜5レッスン。1レッスンで扱う概念は1つ
- 本文では、章をまたいで同じことを重ねて教えない。「扱わないこと」に書いた内容は、該当する章に任せる。前の章の内容に触れるときは「第N章で扱った」と1文で示すだけにする
- 問題では、前の章の知識を使ってよい。特にAIコードレビュー問題は、そのレッスンの論点に加えて、前の章で学んだ問題も含むコードにしてよい（後の章で前の章の知識を使わせて、記憶を定着させるため）。ただし正解は、そのレッスンの論点で決まるようにする
- 「出典の候補」は計画の段階の見込み。生成するときに、Laravel 13.x の公式ドキュメントでページとアンカーが実在するかを確かめ、確かめたものだけを `sources` に書く
- 第14章は新しい知識を学ぶ章ではなく、複数の章の知識を使うレビュー演習（構成は本書の4章）
- 1章を生成したら、その章だけでPRを出す（ブランチ名は `feat/chapterN-content`、コミットは `feat/ 第N章（テーマ）の教材を追加`）

## 4. 第14章のレッスンの構成

第14章は、教材生成ガイド 3章の見出しの代わりに、次の構成にする。

| 見出し | 内容 |
| --- | --- |
| `## 演習の進め方` | 何をレビューするか、どの章の知識を使うか |
| `## レビュー対象のコード` | AIが書いた、動くが問題を複数含むコード（40行以内） |
| `## 見つけるべき問題` | 問題ごとに「何が問題か」「どの章で扱ったか」「どう直すか」 |
| `## 直したコード` | 問題をすべて直したコード |
| `## まとめ` | レビューのときに確かめる観点の一覧 |

- 想起カードは「〜のようなコードを見たら、まず何を確かめるか」を問う。どんなコードかを問いの中に書き、本文やレビュー対象のコードがなくても意味が通るようにする（例: 「コントローラーの中で、リクエストの値をそのまま create() に渡しているコードを見たら、まず何を確かめるか」）
- 問題は、AIコードレビュー問題を2問にする
- `sources` には、使った知識の出典（対象バージョンの公式ドキュメント）を書く

## 5. 生成の順番

章の番号順に生成する（後の章が前の章の内容を前提にするため）。ただし、学習の進み具合に合わせて、先の章を前倒ししてもよい。
