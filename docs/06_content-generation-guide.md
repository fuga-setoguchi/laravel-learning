# 教材生成ガイド

作成日: 2026-11-16
ステータス: 確定（2026-11-16）
参照: [プロジェクト計画書](00_project-plan.md) 2・5章 / [教材フォーマット仕様書](04_content-format.md)

Claude Codeに教材を書かせるときに、毎回このファイルを参照させる。人が読むためのものではなく、生成の指示書である。

## 1. 依頼のしかた

```
docs/06_content-generation-guide.md と docs/04_content-format.md に従い、
第{N}章「{テーマ}」のレッスンを {M} 本作成してください。
章の主な内容: {計画書 5章の「主な内容」}
既存のレッスン: content/ch{NN}/ を確認し、重複しないようにしてください。
作成後、php artisan lessons:import --dry-run を実行し、エラーがなくなるまで修正してください。
```

1回の依頼は1章分までとする（全章を先に作り切らない）。

## 2. 生成する前に確認すること

1. `laravel_version` は、`content/` の既存の教材と同じ値を使う（新しい版に上げるときは、別途まとめて行う）
2. 書く内容を、そのバージョンの公式ドキュメント（`https://laravel.com/docs/{version}/...`）で確認する。確認したページを `sources` に書く
3. 公式ドキュメントで確認できない内容（ブログ・慣習・個人の意見）を書く場合は、本文中で「公式ドキュメントの記載ではなく、一般的な考え方」と明記する
4. 古いバージョンの書き方（例: `app/Http/Kernel.php` でのミドルウェア登録）を、現行の方法として書かない

## 3. レッスンの構成

- 1レッスンで扱う概念は1つ。10〜15分で読み終わり、問題を解ける分量（本文は2,000〜3,500字が目安）
- 本文は次の見出しで構成する

| 見出し | 内容 |
| --- | --- |
| `## 概念` | それが何か。1〜3段落 |
| `## なぜ必要か` | 使う利点、使わないと何に困るか。具体的な場面で示す |
| `## どこに書くか` | どのファイル・どの層に置くか、置かないものは何か（該当しないレッスンは省略可） |
| `## 良い例と悪い例` | 悪い例 → なぜ悪いか → 良い例 の順。コードは短く（各30行以内）、読むだけでわかるものにする |
| `## AIが書きがちな誤り` | AIが生成しがちな、動くが望ましくないコードの例と見分け方 |
| `## まとめ` | 箇条書き3〜5行 |

## 4. 問題の作り方

### 4.1 共通

- 「何か」より「なぜ」「どこに」「どれを選ぶか」を問う。関数名・引数の暗記を問わない
- 本文を読めば答えられる内容にする。本文にない知識を問わない
- 問題文だけで意味が通るように書く（復習では本文なしで、他の章の問題と混ざって出題される）。「上の例で」「このレッスンの」などの表現を使わない

### 4.2 事前の問い（1問）

- 本文を読む前に予想で答える問い。読む動機になる、少し意外な答えのものがよい
- 選択肢は3つ

### 4.3 想起カード（3〜5枚）

- 答えが1〜3文で言えるもの。「〜はなぜか」「〜のとき、どこに書くか」「AとBはどう使い分けるか」
- 答えは「何を思い出せたら『思い出せた』と評価してよいか」がわかるように、要点を明確に書く
- 1枚で1つのことだけを問う

### 4.4 選択式・AIコードレビュー問題（合わせて1〜2問。1問以上はAIコードレビュー問題にする）

- 選択肢は3〜4つ。正解は1つだけ
- 誤りの選択肢は、初学者が実際に選びがちなもの（もっともらしい誤解）にする。明らかな誤りや冗談を入れない
- 正解の選択肢だけが長い・詳しい、という偏りを作らない
- `key` は `a` から順に付ける。正解の `key` は問題ごとに変え、すべて `a` にしない（画面では表示順がシャッフルされるが、教材の確認しやすさのため）
- 「すべて正しい」「どれでもない」は使わない
- AIコードレビュー問題のコードは、実際にAIが書きそうな、**動くが問題のある**コードにする（構文エラーのコードにしない）。コードは15行以内
- 解説には、正解の理由と、主な誤りの選択肢がなぜ違うかを書く

## 5. idの付け方

- レッスン: `ch{章2桁}-l{順番2桁}`。ファイルは `content/ch{章2桁}/l{順番2桁}.md`
- 想起カード: `{レッスンid}-c{1から連番}`、問題: `{レッスンid}-q{1から連番}`
- 既存のレッスンを修正するときは、問題の `id` を変えない。問題を削除した場合、その番号は再利用せず、新しい問題には続きの番号を付ける

## 6. 禁止事項

- 公式ドキュメントの文章をそのまま、または語尾を変えただけで転載しない。自分の言葉で書き、コード例も独自のものにする
- HTMLタグを書かない
- 出典に公式ドキュメント以外のURLを書かない（取り込みでエラーになる）
- 実在しないメソッド・設定・Artisanコマンドを書かない。不確かなものは公式ドキュメントで確認できるまで書かない

## 7. 生成後のセルフチェック

生成したら、次を確認してから完了とする。

- [ ] `php artisan lessons:import --dry-run` がエラーなしで通る（警告も解消する）
- [ ] すべての主張が `sources` のページで確認できる、または一般的な考え方と明記してある
- [ ] 問題文が本文なしで意味が通る
- [ ] 各選択式の正解が1つだけで、誤りの選択肢が明確に誤りである
- [ ] AIコードレビュー問題が1問以上ある
