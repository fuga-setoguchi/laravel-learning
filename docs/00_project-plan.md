# Laravel学習アプリ プロジェクト計画書

作成日: 2026-11-16
更新日: 2026-11-16（精査結果、画面遷移の方針を反映）

## 1. 概要と目的

Laravelの概念・設計判断・ベストプラクティスを学ぶための、自分専用の教材アプリをLaravel（Blade）で開発する。

コーディングAIを使う前提の開発では、関数や文法を暗記することより、「AIが書いたコードがLaravelらしく正しいか」「その処理をどの層・どのファイルに置くべきか」「設計の選択肢から何を選び、なぜそうするのか」を判断できる力が重要になる。本アプリはこの判断力を身につけることを目的とする。

- 公開はしない。ローカル環境で自分だけが使う
- 教材の中身はClaude Codeで生成し、自分は読んで問題を解くことに集中する（ノートを書く作業はしない）
- アプリを作る過程そのものも、Laravelの学習とする

## 2. 学習設計の方針

人は読んだだけでは「理解したつもり」になり、記憶は定着しない。定着させるには、自分で思い出す行為を、間隔を空けて定期的に繰り返す必要がある。本アプリはこの前提で、次の5つの原則に基づいて教材と復習を設計する。

| 原則 | 内容 | アプリでの実現方法 |
| --- | --- | --- |
| 想起練習 | 読む時間より、思い出す時間を多くする | 答えを見る前に頭の中で答えを出す「想起カード」を復習の中心にする |
| 分散学習 | 間隔を空けて繰り返し思い出す | 思い出せたら間隔を広げ、思い出せなければ縮める復習スケジュール |
| 事前テスト | 読む前に予想で答えさせる | 各レッスンの冒頭に「事前の問い」を置く |
| 「なぜ」を問う | 何かより、理由や使いどころを問う | 問題は「なぜそうするのか」「どこに書くべきか」を中心にする |
| 交互練習 | 復習では複数の章を混ぜる | 復習の出題で、できる範囲で同じ章が続かないように並べる |

読んだ直後は答えを覚えているため、レッスン直後に正解しても定着の証拠にはならない。そのため、レッスン直後の回答は復習の段階に数えず、最初の復習は翌日とする。

1日の学習時間は約30分を想定する。毎日の流れは「今日の復習 → 新しいレッスン」の順とし、復習を優先する。1日の復習数に上限は設けない。

## 3. ゴールと完成の定義

MVPは、以下をすべて満たした時点で完成とする。

- [ ] ローカル環境で起動し、ブラウザから利用できる
- [ ] 教材のMarkdownファイルをコマンドで取り込める。必須項目（対象バージョン・出典・問題のidなど）が欠けた教材や、出典URLの形式が不正な教材は取り込みでエラーになる
- [ ] 教材を修正して取り込み直しても、学習記録（レッスンの完了状態・復習の段階）が失われない
- [ ] レッスンを「事前の問い → 本文 → その場で思い出す → 完了」の流れで受講できる
- [ ] レッスン完了時に、そのレッスンの問題が翌日を初回として復習スケジュールに登録される
- [ ] ホーム画面に今日の復習と次のレッスンが表示され、復習結果に応じて次回の復習日が更新される
- [ ] 第1章の教材（3〜5レッスン）が取り込まれ、実際に学習を始められる
- [ ] 静的解析（Larastan）と自動テストが通り、CIで自動実行される

## 4. スコープ

MVPは「教材を取り込み、受講し、復習が回る」ところまでに絞る。それ以外は、使ってみて欲しくなったものからフェーズ2以降で追加する。

| 区分 | 機能 | 内容 |
| --- | --- | --- |
| MVP | 教材の取り込み | Markdownの教材ファイルをArtisanコマンドで取り込む。必須項目と出典URLの形式を検証する |
| MVP | カリキュラム表示 | 章とレッスンの一覧、レッスンごとの完了状態を表示する |
| MVP | レッスン受講 | 事前の問い → 本文 → その場で思い出す → 完了、の流れで受講する |
| MVP | 復習 | 期限が来た問題を章を混ぜて出題し、結果に応じて次回の復習日を決める |
| MVP | ホーム | 今日の復習の件数と、次に受講するレッスンを表示する |
| フェーズ2候補 | 学習記録 | 学習した日、正答率の推移を表示する |
| フェーズ2候補 | 用語集 | サービスコンテナなどの用語をすぐ引けるようにする |
| フェーズ2候補 | 教材の誤り報告 | 誤りや疑問を感じた箇所に印を付け、後で見直せるようにする |
| フェーズ2候補 | 出典リンクの実在確認 | 出典URLに実際にアクセスし、存在しないページを一覧にするコマンド |
| フェーズ2候補 | 検索・ブックマーク | 教材の検索、気になるレッスンの保存 |
| フェーズ2候補 | 復習間隔の高度化 | Ankiなどで使われる、記憶の定着度に応じた間隔計算に変更する |

対象外：公開・デプロイ、ログイン機能（ローカルで自分だけが使うため）、アプリ内からのAI API呼び出し（費用をかけないため）。

## 5. 教材の構成

### カリキュラム（案）

1章あたり3〜5レッスンを目安とする。

| 章 | テーマ | 主な内容 |
| --- | --- | --- |
| 1 | Laravelの全体像 | フレームワークを使う利点、MVC、リクエストのライフサイクル |
| 2 | ディレクトリ構成と設定 | 各フォルダ・ファイルの役割、処理をどこに書くべきか、設定と環境変数（.env、config） |
| 3 | サービスコンテナと依存性の注入 | DIを使う理由、サービスプロバイダ、テストしやすさとの関係 |
| 4 | ルーティングとミドルウェア | それぞれの責務、ミドルウェアに置くべき処理 |
| 5 | コントローラーの責務 | コントローラーを太らせない設計（FormRequest、Action/Service、APIリソース） |
| 6 | Eloquentとデータベース設計 | マイグレーション、Active Recordの長所と短所、リレーション、N+1問題とEager Loading |
| 7 | バリデーションと認可 | FormRequest、Policy、Gateの使い分け |
| 8 | 非同期処理 | キュー、ジョブ、イベントを使うべき場面 |
| 9 | テスト戦略 | 機能テストと単体テストの使い分け、何をテストすべきか |
| 10 | セキュリティ | マスアサインメント、CSRF、XSS、認可漏れ |
| 11 | 例外処理とログ | 例外の扱い方、エラーレスポンス、ログに残すべきこと |
| 12 | パフォーマンス | キャッシュ、インデックス、クエリの最適化 |
| 13 | AIとの協働（総まとめ） | 複数の章の知識を使う、AIが書いたコードの横断的なレビュー演習 |

各レッスンにAIコードレビュー問題を含めるため、第13章は新しい知識を学ぶ章ではなく、総まとめの演習と位置づける。

### 1レッスンの構成

1レッスンは10〜15分で終わる分量とし、1日30分の中で「復習＋新しいレッスン1つ」に収まるようにする。

1. 事前の問い（1問）：本文を読む前に、予想で答える
2. 本文：概念 → なぜ必要か（利点・使わないと困ること）→ 良い例と悪い例（コードは読むだけ）
3. その場で思い出す：本文を閉じた状態で、このレッスンの想起カードに頭の中で答え、答えを開いて確認する。ここでの結果は記録しない
4. 完了：このレッスンの問題（想起カード3〜5枚、選択式・AIコードレビュー問題1〜2問）を、翌日を初回として復習スケジュールに登録する

### 教材ファイルの形式

教材は1レッスン1ファイルのMarkdownとし、先頭のメタ情報（front matter）に属性と問題を書く。問題には、教材を修正しても変わらない固定のidを付ける。

```markdown
---
id: ch03-l02
chapter: 3
order: 2
title: なぜコントローラーでnewせずに注入するのか
laravel_version: "12.x"
sources:
  - title: Service Container
    url: https://laravel.com/docs/12.x/container
pre_question: { ... }
recall_cards:
  - id: ch03-l02-c1
    ...
questions:
  - id: ch03-l02-q1
    ...
---

（本文）
```

### 教材の正確さに関する要件

AIが生成した教材には誤りが含まれる可能性があるため、以下を必須とする。

- 各レッスンに、対象のLaravelのバージョン（laravel_version）を記載する
- 各レッスンに、根拠となる公式ドキュメントのページ（sources）を1件以上記載する
- 出典URLは `https://laravel.com/docs/` で始まり、URL内のバージョンが laravel_version と一致すること
- 取り込みコマンドは、これらを満たさない教材をエラーとして取り込まない
- レッスン画面には、対象バージョンと出典のリンクを常に表示する
- 教材は自分の言葉で書き、公式ドキュメントの文章をそのまま転載しない

laravel_versionの値は着手時点の最新安定版に合わせる（上記は記載例）。

## 6. 復習の仕組み

### 問題の種別

| 種別 | 出題場面 | 回答方法 | 採点 |
| --- | --- | --- | --- |
| 事前の問い | レッスン冒頭のみ | 予想で選ぶ | 正誤を表示するのみ（復習には入れない） |
| 想起カード | レッスン本文の直後・復習 | 頭の中で答えてから答えを開く | 復習では自己評価（思い出せた / あいまい / 思い出せなかった）。レッスン直後は記録しない |
| 選択式 | 復習 | 選択肢から選ぶ | 自動採点 |
| AIコードレビュー問題 | 復習 | 「AIが書いたこのコードの問題点はどれか」を選ぶ | 自動採点 |

想起カードを復習の中心とし、選択式とAIコードレビュー問題で、自己評価の甘さを補う。

### 復習間隔

問題ごとに段階を持ち、段階に応じて次回の復習日を決める。レッスン完了時の初期状態は「段階1・次回の復習日は翌日」とする。

| 段階 | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- | --- |
| 次回までの日数 | 1日 | 3日 | 7日 | 14日 | 30日 | 60日 |

段階6に達した後は、60日間隔で出題を続ける。

### 評価と段階の更新ルール

| 結果 | 段階の更新 |
| --- | --- |
| 思い出せた / 正解 | 1つ上の段階へ進み、その段階の日数後を次回の復習日とする |
| あいまい | 同じ段階のまま、その段階の日数後を次回の復習日とする |
| 思い出せなかった / 不正解 | 段階1に戻し、翌日を次回の復習日とする。加えて、その日の復習の最後にもう一度出題する |

その日の最後に再出題した問題の結果は練習扱いとし、段階や次回の復習日は変更しない。

### 出題順と次の問題の決め方

出題の順番はセッションなどに保持せず、リクエストのたびにDBの状態から「次に出す問題」を1問決める。途中でブラウザを閉じたり再読み込みしたりしても、続きから正しく再開できるようにするためである。

1. 期限が来た問題（期限切れを含む）があれば、その中から出題する。期限の古い順を基本とし、直前に回答した問題（review_logsの最新）と同じ章の問題は、できる範囲で避ける（対象が1つの章しかない場合は、その章の問題を続けて出す）
2. 期限が来た問題がなくなったら、今日「思い出せなかった / 不正解」で、まだ練習扱いの再出題をしていない問題を出題する
3. どちらもなければ、「今日の復習は完了」を表示する

- 期限が来た問題はすべて出題する。1日の上限は設けない
- 毎日の流れは「今日の復習 → 新しいレッスン」とし、復習を先に表示する

### 日付の扱い

アプリのタイムゾーンは Asia/Tokyo とし、日付の区切りは0時とする。「今日の復習」は、次回の復習日が今日以前の問題とする。

## 7. 画面・コマンド・データの概要

MVPは画面4つ、コマンド1つ、テーブル8つで構成する。詳細は各設計書で確定する。

### 画面遷移の方針

画面はBladeによるサーバーサイドレンダリングで作り、JavaScriptによる動的な画面更新は行わない。

- 1つの操作を1回の画面遷移とする。回答や評価はフォームでPOSTし、処理後は結果の画面へリダイレクトする（PRGパターン）。再読み込みで同じ回答が二重に送信されないようにする
- 答えの開閉は、HTMLの `<details>` と `<summary>` で実現し、JavaScriptを使わない
- ブラウザの「戻る」などで古い画面から送信された場合に備え、サーバー側で検証する。期限が来ていない問題への評価や、すでに今日の練習を終えた問題への再送信は記録しない

### 画面

| ID | 画面名 | 概要 |
| --- | --- | --- |
| SCR-01 | ホーム | 今日の復習の件数と開始ボタン、次に受講するレッスン、全体の進捗を表示する |
| SCR-02 | カリキュラム | 章とレッスンの一覧、レッスンごとの完了状態、章ごとの進捗率を表示する。任意のレッスンを選んで受講できる |
| SCR-03 | レッスン | 事前の問い → 本文 → その場で思い出す → 完了、を段階ごとの画面で順に進める。対象バージョンと出典を表示する |
| SCR-04 | 復習 | 次に出す問題を1問ずつ出題し、回答・自己評価を受け付ける。選択式は回答後に正誤と解説の画面を表示する |

レッスン（SCR-03）は、段階ごとに画面を分ける。画面が分かれることで、「本文を閉じた状態で思い出す」を自然に実現する。

| 段階 | 画面 | 操作 |
| --- | --- | --- |
| 1 | 事前の問い | 予想で選んで送信する |
| 2 | 本文 | 事前の問いの正誤を表示し、本文を読む。「思い出す」へ進む |
| 3 | その場で思い出す | 本文は表示しない。想起カードの答えを `<details>` で開いて確認し、「完了」を送信する |
| 4 | 完了 | 復習に登録したことを表示し、ホームへ戻る |

復習（SCR-04）は、問題の種別ごとに次の流れとする。

| 種別 | 流れ |
| --- | --- |
| 想起カード | 問いを表示し、答えは `<details>` で開く。3つの評価ボタン（思い出せた / あいまい / 思い出せなかった）のいずれかを送信し、次の問題へ進む |
| 選択式・AIコードレビュー問題 | 選択肢を選んで送信すると、正誤と解説の画面に切り替わる。「次へ」で次の問題へ進む |

「次に受講するレッスン」は、未完了のレッスンのうち章・順番が最も前のものとする。カリキュラム画面からは、順番に関係なく任意のレッスンを受講できる。

### コマンド

| ID | コマンド | 概要 |
| --- | --- | --- |
| CMD-01 | lessons:import | 教材フォルダのMarkdownを読み込み、検証してDBに取り込む。教材・問題は固定のidで照合して追加・更新し、学習記録には触れない |

教材ファイルから問題が削除された場合の扱い（復習対象から外すなど）は、コマンド設計書で確定する。

### テーブル

教材のデータ（取り込みで更新される）と、学習記録（取り込みでは変更しない）を分けて管理する。

| 区分 | テーブル | 主な項目 |
| --- | --- | --- |
| 教材 | chapters | id、番号、タイトル |
| 教材 | lessons | id（教材のid）、chapter_id、順番、タイトル、本文、laravel_version、事前の問い |
| 教材 | lesson_sources | id、lesson_id、タイトル、URL |
| 教材 | questions | id（教材の固定id）、lesson_id、種別、問題文、解答・解説 |
| 教材 | question_choices | id、question_id、選択肢、正解かどうか |
| 学習記録 | lesson_progress | lesson_id、完了日時 |
| 学習記録 | review_states | question_id、段階、次回の復習日 |
| 学習記録 | review_logs | id、question_id、回答日時、結果、練習扱いかどうか |

## 8. 技術スタックと品質方針

画面はBladeで作り、フロントエンドに時間を取られずLaravelそのものに集中する。各ツールのバージョンは着手時点の最新安定版で確定する。

| 領域 | 採用技術 | 用途 |
| --- | --- | --- |
| バックエンド | PHP / Laravel | アプリ本体、教材取り込みコマンド |
| 画面 | Blade | サーバーサイドレンダリング。フォーム送信と画面遷移で構成し、答えの開閉は `<details>` で行う |
| DB | SQLite | ローカルで自分だけが使うため、設定不要で軽いものを選ぶ |
| Markdown | Laravel標準のMarkdown変換（league/commonmark） | 教材本文の表示 |
| コードのハイライト | highlight.js（CDNから読み込み、Node.js不要） | 本文中のコード表示。JavaScriptを使うのはこの表示用途のみとする |
| 静的解析・整形 | Larastan / Laravel Pint | 型チェック、コード規約 |
| テスト | Pest | 機能テスト・単体テスト |
| CI | GitHub Actions | 静的解析・テストの自動実行 |

品質方針：

- PHPは全ファイルで `declare(strict_types=1)` と型宣言を行い、Larastanは高めのレベルで通す
- 復習間隔の計算（段階の更新、次回の復習日、出題順の並べ替え）は独立したクラスにまとめ、単体テストで網羅する。日付に依存するテストは、時刻を固定して実行する
- 教材取り込みの検証（必須項目の欠落、不正な形式、出典URLの不一致）と、取り込み直しで学習記録が保たれることは、テストで確認する
- 次の問題の決め方（章の回避、練習扱いの再出題、完了判定）と、古い画面からの送信や二重送信を記録しないことは、機能テストで確認する
- URL短縮サービスから流用するのは、静的解析（Larastan・Pint）、テスト（Pest）、CI（GitHub Actions）の設定のみとする。MySQL・React・Dockerの構成は持ち込まない

| 9 | 自動テスト設計書 | 画面・コマンド・ロジックごと | docs/tests/ 配下 |
| 10 | 教材生成ガイド | 1ファイル | docs/06_content-generation-guide.md |
| 11 | 教材 | レッスンごと | content/ch01/l01.md ほか |

教材生成ガイドには、Claude Codeに教材を書かせるときの指示（レッスンの構成、問題の作り方、「なぜ」を問うこと、問題に固定のidを付けること、対象バージョンと出典の記載が必須であること、公式ドキュメントの文章を転載しないこと）をまとめ、章ごとの教材生成で毎回参照させる。

運用ルール：

1. 設計書のIDは本書のID（SCR-01、CMD-01など）を引き継ぐ
2. 設計書が確定するまで実装に入らない
3. 実装中に設計を変える場合は、先に設計書を更新する
4. Claude Codeへの依頼時は、本書と関連する設計書を参照させる
5. 学習記録を消す操作（`migrate:fresh` など）は、学習用のDBでは実行しない。開発・テストには別のDBファイルを使う
6. 学習用のSQLiteファイルは、定期的に別の場所へコピーしてバックアップする

## 10. 進め方とリスク

進め方：

1. 計画：本書を確定する
2. 設計：要件定義書から自動テスト設計書までをClaude Codeで作成し、レビューして確定する。教材フォーマット仕様書と教材生成ガイドもここで確定する
3. 実装：環境構築、教材取り込み、レッスン受講、復習の順に実装する
4. 教材：第1章の教材を生成・取り込みし、実際に学習を始める
5. 運用：毎日30分の学習を続けながら、2章以降の教材を少しずつ生成する。使っていて欲しくなった機能をフェーズ2として追加する

| リスク | 対策 |
| --- | --- |
| AIが生成した教材に誤りがある | 対象バージョンと出典の記載を必須にし、出典URLの形式を取り込み時に検証する。違和感があれば公式ドキュメントで確認する。フェーズ2で誤り報告機能と出典リンクの実在確認を検討する |
| 教材の修正で学習記録が壊れる | 問題に固定のidを持たせ、教材と学習記録のテーブルを分ける。取り込み直しで記録が保たれることをテストで確認する |
| 自己評価が甘くなり、覚えたつもりになる | 想起カードに加えて自動採点の問題を出題し、自己評価と正答の差に気づけるようにする |
| 休んだ日に復習が溜まり、開かなくなる | 上限は設けない方針とするが、溜まりすぎて負担に感じた場合は、上限や翌日への繰り越しをフェーズ2で検討する |
| 学習記録が消える | 学習用DBで記録を消す操作を行わず、定期的にバックアップする |
| 教材生成に時間を取られ、学習が進まない | 教材は章ごとに必要な分だけ生成し、全章を先に作り切らない |
| アプリを作り込みすぎて、学習が始まらない | MVPは4画面とコマンド1つに絞り、第1章で学習を始めることを完成の条件にする |
