## 概念

**認可漏れ**は、URL やフォームの id を書き換えるだけで、他人のデータを見たり変えたりできてしまう問題です。

```php
// /orders/15 を /orders/16 に書き換えると、他人の注文が見える
Route::get('/orders/{order}', [OrderController::class, 'show'])->middleware('auth');

public function show(Order $order)
{
    return view('orders.show', compact('order'));
}
```

`auth` ミドルウェアは「ログインしているか」を確かめるだけで、ルートモデル結合も id でデータを探すだけです。どちらも「このデータを、この人が扱ってよいか」は確かめません。認証と認可の違い、Policy の書き方と確かめる場所は第8章で扱いました。このレッスンでは、確かめ忘れが起きやすい場所と、その防ぎ方を扱います。

## なぜ必要か

認可漏れは、画面からは気づきにくい問題です。画面に出すリンクは本人のデータのものだけなので、ふつうに使っている限り、他人のデータは見えません。しかし、利用者は URL やフォームの値を自由に書き換えて送れます。

id が連番なら、数字を1つずつ変えるだけで、ほかの利用者の注文・請求書・個人情報を順に取り出せます。一覧の画面で他人のデータが見えるのも、同じ問題です。1か所の確かめ忘れが、すべての利用者のデータの漏えいにつながります。

## どこに書くか

| 場面 | 防ぎ方 |
| --- | --- |
| 自分のデータの一覧 | `$request->user()->orders()->latest()->get()` のように、リレーションから取り出す |
| URL で指定された1件 | ルートの `->can('view', 'order')`、または `Gate::authorize('view', $order)` |
| 本人のデータの中から探す | `$request->user()->orders()->findOrFail($id)`（なければ 404） |
| 親子の組み合わせの URL | `->scopeBindings()`（第4章） |

公式ドキュメントによると、リレーションのメソッドを呼ぶと、そのリレーションに絞り込んだクエリを組み立てられます。ログインしているユーザーのリレーションから取り出せば、他人のデータはそもそも取り出せません。

他人のデータに 403 を返すと、「その id のデータはある」ことが伝わります。存在そのものを隠したいときは、Policy から `Response::denyAsNotFound()` を返して 404 にします。公式ドキュメントも、404 でデータを隠すのはよくあるやり方なので、このメソッドを用意していると書いています。

id を推測しにくい UUID にしても、id を知られれば扱えるので、認可の代わりにはなりません（一般的な考え方）。

## 良い例と悪い例

悪い例: リクエストの user_id で絞り込む。

```php
$orders = Order::where('user_id', $request->input('user_id'))->get();
```

なぜ悪いか: user_id を書き換えれば、他人の注文の一覧が見えます。

良い例: 一覧はリレーションから取り出し、1件は Policy で確かめる。

```php
$orders = $request->user()->orders()->latest()->get();

Route::get('/orders/{order}', [OrderController::class, 'show'])
    ->middleware('auth')
    ->can('view', 'order');
```

## AIが書きがちな誤り

- 一覧を `Order::all()` や、リクエストの `user_id` で絞り込んで取り出す
- 表示やダウンロードの処理で、更新や削除と違って認可を確かめない
- Policy を作っただけで、ルートやコントローラーで確かめない
- id を UUID にすれば、他人のデータは取り出せないと考える

id を受け取る処理を見たら、「この id を別の利用者のものに書き換えたらどうなるか」を考えましょう。

## まとめ

- `auth` ミドルウェアやルートモデル結合は、データの持ち主を確かめない
- 一覧はログインしているユーザーのリレーションから取り出す
- 1件のデータは Policy で確かめる。表示やダウンロードも忘れない
- 存在を隠したいときは `denyAsNotFound()` で 404 にする
