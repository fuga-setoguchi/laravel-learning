## 概念

**SQL インジェクション**は、利用者の入力を SQL の文に埋め込んだとき、入力に書かれた SQL が実行されてしまう攻撃です。

```php
// 悪い例: 入力を SQL の文字列に埋め込む
DB::select("select * from users where email = '{$email}'");
```

`$email` にシングルクォートと SQL を書けば、条件を書き換えたり、別のテーブルのデータを取り出したりできます。

公式ドキュメントによると、クエリビルダーは PDO の**パラメータのバインド**を使って、SQL インジェクションを防ぎます。値は SQL の文とは別に渡されるので、クォートや SQL の語を含んでいても、ただの値として扱われます。

```php
// 良い例: 値はバインドされる
DB::table('users')->where('email', $email)->first();
```

## なぜ必要か

SQL インジェクションが成り立つと、条件を外してほかの利用者のデータを取り出したり、データを書き換えたり消したりできます。1か所の埋め込みで、データベース全体が危険になります。

Eloquent のモデルの `Post::where(...)` も、内部ではクエリビルダーを使うので、同じようにバインドされます。「Eloquent だから安全」なのではなく、「値をバインドしているから安全」なので、Eloquent の中でも raw のメソッドに埋め込めば危険です（Laravel 本体の実装による動きと、一般的な考え方）。

クエリビルダーや Eloquent の `where` を使っていれば守られるので、問題になるのは、生の SQL を書く箇所です。公式ドキュメントは、raw の式は文字列のまま SQL に入るので、SQL インジェクションを起こさないよう十分に注意するよう書いています。raw の式を使うクエリについて、Laravel は SQL インジェクションから守られていると保証できない、とも書いています。

## どこに書くか

| 場面 | 書き方 |
| --- | --- |
| 条件 | `where('title', 'like', "%{$keyword}%")` |
| raw のメソッドで値を使う | `whereRaw('price > ?', [$price])` のように、値は配列で渡す |
| 生の SQL を実行する | `DB::select('select * from users where id = :id', ['id' => $id])` |
| 並べ替えの列を選ばせる | 許す列名の一覧を決め、その中の値だけを `orderBy` に渡す |

公式ドキュメントによると、`whereRaw` などは、2つ目の引数でバインドする値の配列を受け取れます。`DB::select` も、`?` や `:id` のような名前の場所に値をバインドできます。

注意が必要なのは列名です。公式ドキュメントによると、PDO は列名のバインドに対応していないので、並べ替えの列を含め、利用者の入力で列名を決めさせてはいけません。許す列名の一覧で絞ります（一覧で絞るのは一般的な考え方）。

## 良い例と悪い例

悪い例: 検索のキーワードを、raw の式に埋め込む。

```php
Post::whereRaw("title LIKE '%{$keyword}%'")->get();
```

なぜ悪いか: キーワードにクォートと SQL を書けば、条件を書き換えられます。

良い例: 値をバインドし、列名は一覧で絞る。

```php
$sort = in_array($request->input('sort'), ['created_at', 'title', 'views'], true)
    ? $request->input('sort')
    : 'created_at';

Post::where('title', 'like', "%{$keyword}%")
    ->orderBy($sort, 'desc')
    ->get();
```

## AIが書きがちな誤り

- `whereRaw`・`selectRaw`・`DB::select` の文字列に、入力を埋め込む
- 並べ替えの列名に、リクエストの値をそのまま使う
- 検証の規則（`string`・`max`）や `trim` で、SQL インジェクションを防げると考える。公式ドキュメントによると、クエリビルダーはバインドで守るので、渡す文字列を自分で掃除する必要はない。対策はバインドで、文字列の加工ではない
- 絞り込みの列名（`where($request->input('field'), ...)`）に、リクエストの値を使う
- 複雑な条件を、クエリビルダーで書けるのに raw の式で書く

raw のメソッドや生の SQL を見たら、「利用者の入力が、バインドされずに文字列に入っていないか」を確かめましょう。

## まとめ

- クエリビルダーは、パラメータのバインドで SQL インジェクションを防ぐ
- raw の式や生の SQL に、入力を埋め込まない。値は `?` や名前でバインドする
- 列名はバインドできないので、許す列名の一覧で絞る
- 対策はバインドで、検証の規則や `trim` のような文字列の加工ではない（公式ドキュメントも、渡す文字列を自分で掃除する必要はないとしている）
