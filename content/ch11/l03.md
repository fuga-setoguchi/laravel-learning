## 概念

**XSS**（クロスサイトスクリプティング）は、利用者が入力した文字列に JavaScript を仕込み、それをほかの利用者の画面で実行させる攻撃です。

公式ドキュメントによると、Blade の `{{ }}` は、XSS 攻撃を防ぐため、自動で PHP の `htmlspecialchars` 関数を通します。山かっこや引用符などが HTML の特殊文字に変換されるので、値にタグが含まれていても、ブラウザは文字として表示します。

```blade
{{-- エスケープされる。タグは文字として表示される --}}
{{ $comment->body }}

{{-- エスケープされない。タグや JavaScript がそのまま働く --}}
{!! $comment->body !!}
```

エスケープを外すのが `{!! !!}` です。公式ドキュメントも、利用者が入力した内容を出すときは十分に注意するよう書いています。

## なぜ必要か

XSS が成り立つと、攻撃者の JavaScript が、ほかの利用者のブラウザで、あなたのアプリの画面として実行されます。画面を書き換えて偽の入力欄を出したり、その利用者として勝手に操作したり、表示している情報を外に送ったりできます（一般的な考え方）。

`{{ }}` を使っていれば Blade が守ってくれるので、問題になるのは `{!! !!}` を使った箇所です。利用者の入力が少しでも混ざっていれば、そこが入り口になります。「管理者が書いた文章だから」「改行を出したいだけだから」という理由でエスケープを外すと、入力する人や経路が後から増えたときに守れなくなります。

コメントや記事のように、保存してから表示するデータは特に危険です。悪意のある文字列が一度保存されると、その画面を開いたすべての利用者のブラウザで、くり返し実行されます。入力を受け取るときではなく、出力するときにエスケープするのが基本です（一般的な考え方）。

## どこに書くか

| 出したいもの | 書き方 |
| --- | --- |
| 利用者の入力を含む値 | `{{ }}`（いつもこれ） |
| 改行を含む本文 | `{{ }}` で出し、改行は CSS の `white-space` で表す |
| JavaScript に渡す配列 | `Js::from($array)` |
| アプリが自分で組み立てた、利用者の入力を含まない HTML | `{!! !!}`（ほとんど使わない） |

使い分けのうち、改行と `{!! !!}` の扱いは一般的な考え方です。

公式ドキュメントによると、配列を JavaScript に渡すときは、`json_encode` を自分で呼ぶ代わりに `Js::from` を使います。script の中で `var app = {{ Js::from($array) }};` のように書きます。`Js::from` は、すでにある変数を JSON にして出すためだけに使うよう注意されています。

利用者に太字や見出しを書かせたいときも、`{!! !!}` でそのまま出すのではなく、許すタグを決めた無害化の処理を通すか、Markdown のような記法から安全に変換します（一般的な考え方）。

## 良い例と悪い例

悪い例: 改行を出すために、エスケープを外す。

```blade
{!! nl2br($comment->body) !!}
```

なぜ悪いか: `nl2br` は改行の位置にタグを足すだけで、本文はエスケープされません。本文の JavaScript がそのまま動きます。

良い例: エスケープして出し、改行は CSS で表す。

```blade
{{-- 本文を囲む要素に white-space: pre-line を指定する --}}
{{ $comment->body }}
```

## AIが書きがちな誤り

- 改行や太字を出すために、利用者の入力を `{!! !!}` で出す
- 「管理者しか書かない」ことを理由に、エスケープを外す
- 配列を JavaScript に渡すときに、`{!! json_encode($data) !!}` と書く
- 検証の規則（`string`・`max`）で、タグを防げると考える
- 利用者が入力した URL をリンク先に出すとき、`{{ }}` でエスケープすれば安全だと考える。`javascript:` で始まる URL はエスケープしてもリンクとして働くので、受け取るときに http・https の URL だけを許す（一般的な考え方）

`{!! !!}` を見たら、「この値に、利用者の入力が少しでも混ざる経路はないか」を確かめましょう。

## まとめ

- `{{ }}` は `htmlspecialchars` でエスケープするので、XSS を防げる
- `{!! !!}` はそのまま出すので、利用者の入力が混ざれば XSS になる
- 改行は CSS で表し、JavaScript への受け渡しは `Js::from` を使う
- エスケープを外してよいのは、利用者の入力を含まない HTML だけ
