## 概念

例外を**握りつぶす**とは、`catch` で例外を受け止め、記録も投げ直しもせずに、何もなかったように処理を続けることです。

```php
try {
    $rate = $this->fetchRate();
} catch (Exception $e) {
    // 何もしない
}
```

例外は「想定どおりに進まなかった」ことを伝える仕組みです。握りつぶすと、その知らせが途中で消えます。トランザクションの中で握りつぶすとロールバックされないこと（第7章）、ジョブの中で握りつぶすと成功したことになり、リトライされないこと（第9章）は、前の章で扱いました。このレッスンでは、コントローラーやサービスでの扱い方を扱います。

## なぜ必要か

握りつぶされた例外は、ログに残らず、利用者にも運用者にも伝わりません。外部の API が何日も落ちていたのに誰も気づかない、ということが起きます（一般的な考え方）。

さらに、失敗したのに処理が続くと、間違った値のまま先へ進みます。為替のレートが取れずに `null` が返り、それを掛け算に使えば、0 円の価格ができてしまいます。例外が起きた場所から離れたところで、わかりにくい不具合として表れます。

## どこに書くか

例外を受け止めるかどうかは、「その場で意味のある対処ができるか」で決めます（一般的な考え方）。

| 状況 | 扱い方 |
| --- | --- |
| その場で対処できない | `catch` しない。Laravel の例外の処理に任せる |
| 失敗しても続けてよいが、記録は必要 | `catch` して `report($e)` を呼ぶ |
| 代わりの値で続けたい | `rescue(fn () => ..., $default)` |
| 利用者向けのメッセージに変えたい | 対処できる例外の種類だけを `catch` し、`report($e)` も呼ぶ |

公式ドキュメントによると、`report` は、エラーページを表示せずに例外を報告します。`rescue` は、渡したクロージャで起きた例外を受け止めて、既定の値を返し、受け止めた例外は報告します。どちらも、処理を続けながら記録を残せます。

`catch (Throwable $e)` のように何でも受け止めると、想定した失敗だけでなく、コードの不具合まで同じ扱いになります。受け止める例外は、対処できる種類に絞ります。

別の例外に包み直して投げるときは、元の例外を `previous` に渡します。元の例外の内容とスタックトレースが残るので、ログから本当の原因をたどれます（PHP の例外の仕組みと、一般的な考え方）。

```php
} catch (RequestException $e) {
    throw new PaymentFailedException('決済に失敗しました', previous: $e);
}
```

## 良い例と悪い例

悪い例: 受け止めて `null` を返すだけ。

```php
} catch (Exception $e) {
    return null;
}
```

なぜ悪いか: 失敗が記録されず、呼ぶ側は `null` のまま計算を進めかねません。

良い例: 記録を残し、前回のレートがあれば使う。なければ例外を投げて、価格の計算を止める。

```php
public function usdToJpy(): float
{
    return rescue(
        fn () => Http::timeout(3)->get($this->url)->throw()->json('rate'),
        fn () => Cache::get('last_usd_jpy_rate')
            ?? throw new ExchangeRateUnavailableException('為替のレートを取れません'),
    );
}
```

代わりの値は、その値で処理を進めても困らない場合にだけ使います。決め打ちの値で価格を計算すると、それ自体が間違った値で処理を進めることになります（一般的な考え方）。

## AIが書きがちな誤り

- `catch` の中を空にするか、`null`・`false` を返すだけにする
- `catch (Throwable $e)` で何でも受け止め、利用者向けのメッセージだけを返す
- エラーを消すことを目的に、try / catch で囲む
- 受け止めた後に `report($e)` を呼ばず、記録を残さない

`catch` を見たら、「この失敗は、誰かに伝わるか」「この後の処理は、正しい値で進むか」を確かめましょう。try / catch が多いコードほど、どこで失敗が消えているかを見落としやすくなります。

## まとめ

- 例外を受け止めて何もしないと、失敗が誰にも伝わらず、間違った値で処理が進む
- その場で対処できないなら、`catch` せずに Laravel に任せる
- 続けるなら `report($e)` で記録し、代わりの値は `rescue` などではっきり決める
- 受け止める例外の種類は、対処できるものに絞る
