## 概念

第3章の最初のレッスンで、依存を注入するとテストで偽物に差し替えられる、と扱いました。このレッスンでは、実際にどう差し替えるかを扱います。

テストで使う偽物の1つが**モック**です。モックは、本物の代わりに渡すオブジェクトで、「このメソッドが呼ばれたら、この値を返す」「このメソッドが呼ばれることを期待する」と決めておけます。

Laravel では、コンテナにモックを登録すると、コンテナが依存を作るときに本物の代わりにモックを渡します。テストでは `$this->mock()` を使うと、モックの作成と登録をまとめて行えます。

```php
use Mockery\MockInterface;

test('注文を確定できる', function () {
    $this->mock(PaymentGateway::class, function (MockInterface $mock) {
        $mock->expects('charge')->andReturn(true);
    });

    $this->post('/orders', ['amount' => 1000])
        ->assertRedirect('/orders/done');
});
```

## なぜ必要か

この差し替えが効くのは、コントローラーが `PaymentGateway` をコンテナから受け取っているからです。コントローラーの中で `new PaymentGateway()` と書いていると、コンテナを通らないので、登録したモックは使われません。つまり、注入で受け取ることが、テストで差し替えるための前提です。

ファサードも同じ仕組みで差し替えられます。`Cache::get()` は静的メソッドのように見えますが、実際にはコンテナから取り出したオブジェクトに処理を渡しています。公式ドキュメントは、ふつうの静的メソッドと違って、ファサードはモックにできると説明しています。

```php
Cache::expects('get')->with('key')->andReturn('value');
```

## どこに書くか

| 差し替えたいもの | テストでの書き方 |
| --- | --- |
| コンストラクタやメソッドで注入されるサービス | `$this->mock(クラス::class, ...)` |
| ファサード（`Cache` など） | `Cache::expects(...)` |
| 設定の値 | `Config::set(...)` で値を入れる（モックにしない） |
| リクエストの入力 | `get`・`post` などの HTTP テストのメソッドに渡す（`Request` ファサードをモックにしない） |

公式ドキュメントは、`Config` ファサードや `Request` ファサードはモックにせず、上の表のように値を渡すよう勧めています。キューやメールなど一部の機能には、送信の代わりに記録だけを行う `fake` が用意されています（第10章で扱います）。

## 良い例と悪い例

悪い例: モックを作っただけで、コンテナに登録しない。

```php
$gateway = Mockery::mock(PaymentGateway::class, function (MockInterface $mock) {
    $mock->expects('charge')->andReturn(true);
});

$this->post('/orders', ['amount' => 1000]);
```

なぜ悪いか: コンテナはこのモックを知らないので、コントローラーには本物が渡され、決済 API が呼ばれます。

良い例: `$this->mock()` で作成と登録をまとめて行う（「概念」のコードを参照）。

## AIが書きがちな誤り

- `Mockery::mock()` でモックを作るだけで、コンテナに登録しない
- コードの中で `new` しているサービスを、テストでモックにしようとする（注入に直すのが先）
- 設定の値を変えるために、`Config` ファサードをモックにする

テストでモックを見つけたら、「このモックは、テストするコードに本当に渡っているか」を確かめましょう。

## まとめ

- テストでの差し替えは、コンテナにモックを登録し、コンテナが依存を作るときに渡させる仕組み
- `$this->mock()` でモックの作成と登録をまとめて行える
- コードの中で `new` していると、差し替えられない。注入で受け取ることが前提
- ファサードは `Cache::expects()` のようにモックにできる。ただし `Config` と `Request` はモックにせず、値を渡す
