## 概念

**インターフェース**は、「このメソッドを持っている」という約束だけを決めた型です。

```php
interface SmsSender
{
    public function send(string $to, string $message): void;
}
```

この約束を守るクラス（実装）は、いくつあってもかまいません。本番で使う `TwilioSmsSender`、開発中にログへ書くだけの `LogSmsSender` などです。

使う側がインターフェースを型に書くと、コンテナは「どの実装を渡せばよいか」を知る必要があります。それを登録するのが、インターフェースと実装の結合です。

```php
// AppServiceProvider の register メソッド
$this->app->bind(SmsSender::class, TwilioSmsSender::class);
```

公式ドキュメントでは、インターフェースに属性を付けて登録する方法も紹介されています。

```php
use Illuminate\Container\Attributes\Bind;

#[Bind(TwilioSmsSender::class)]
#[Bind(LogSmsSender::class, environments: ['local', 'testing'])]
interface SmsSender { /* ... */ }
```

`environments` を指定すると、その環境でだけ別の実装を使えます。

## なぜ必要か

公式ドキュメントは、コンテナを直接扱う必要がある代表的な場面として、インターフェースを型に書く場合を挙げています。

インターフェースに依存すると、使う側は「SMS を送れる何か」だけを知っていればよくなります。本番の送信サービスを別の会社に替えるときも、登録を1か所変えるだけで、使う側のコードは変わりません。

## どこに書くか

| やりたいこと | 置き場所 |
| --- | --- |
| どの実装を渡すか決める | サービスプロバイダの `register`、またはインターフェースの `#[Bind]` 属性 |
| 実装を使う | インターフェースを型に書いて、コンストラクタで受け取る |
| 環境ごとに実装を変える | 結合の側で分ける（`#[Bind]` の `environments` など） |

インターフェースを作るのは、差し替える理由があるところだけにします。実装が1つしかなく、差し替える予定もないクラスにまでインターフェースを用意すると、ファイルが増えて読みにくくなるだけです（一般的な考え方）。

## 良い例と悪い例

悪い例: 使う側で実装を選ぶ。

```php
$sender = app()->environment('production')
    ? new TwilioSmsSender(config('services.twilio.token'))
    : new LogSmsSender();
```

なぜ悪いか: SMS を送る箇所すべてに同じ分岐が必要になり、書き忘れると開発中に本物の SMS が送られます。テストで偽物を渡すこともできません。

良い例: インターフェースを受け取り、実装の選び方は登録に任せる。

```php
class SendLoginCode
{
    public function __construct(private SmsSender $sender) {}

    public function handle(User $user, string $code): void
    {
        $this->sender->send($user->phone, "認証コード: {$code}");
    }
}
```

## AIが書きがちな誤り

- 使う側で `if` や三項演算子を使って、環境ごとに実装を `new` し分ける
- インターフェースを型に書いたのに、結合を登録し忘れる（解決できずにエラーになる）
- 実装が1つしかないクラスにも、機械的にインターフェースを作る

インターフェースを見つけたら、「どこで実装が結び付けられているか」「差し替える理由はあるか」を確かめましょう。

## まとめ

- インターフェースは「何ができるか」の約束。実装はいくつあってもよい
- インターフェースを型に書くなら、どの実装を渡すかを `bind` か `#[Bind]` で登録する
- 実装の選び方を登録の1か所にまとめると、使う側を変えずに差し替えられる
- インターフェースは、差し替える理由があるところだけに作る（一般的な考え方）
