## 概念

前のレッスンでは、依存をコンストラクタで受け取る利点を扱いました。では、渡すオブジェクトはどこで作られるのでしょうか。

Laravel のサービスコンテナは、コンストラクタの**型宣言**を手がかりに依存を作ります。

```php
class ReportService
{
    public function __construct(
        private PdfRenderer $renderer,
        private ChartBuilder $charts,
    ) {}
}
```

コントローラーが `ReportService` を受け取ると、コンテナは次のように動きます。

1. `ReportService` のコンストラクタの型を見る
2. `PdfRenderer` と `ChartBuilder` が必要だとわかる
3. それぞれのコンストラクタも見て、同じように作る
4. 作ったものを渡して `ReportService` を作る

公式ドキュメントは、依存がないクラスや、ほかの具象クラス（インターフェースでないクラス）にだけ依存するクラスは、コンテナに何も教えなくても作れると説明しています。

## なぜ必要か

自動で作られるので、依存が増えても、使う側やサービスプロバイダを直す必要がありません。`ReportService` に新しい依存を足すときは、コンストラクタに1行足すだけです。

逆に言えば、不要な結合を書くと、この利点を自分で捨てることになります。具象クラスのために `bind` で組み立てを手書きすると、コンストラクタが変わるたびにその手書きも直す必要があります。公式ドキュメントも、インターフェースに依存しないクラスは、コンテナがリフレクションで自動的に解決できるので、結合する必要がないとしています。

公式ドキュメントの Binding Basics の最初の例は、`bind` で具象クラスを組み立てる形をしています。これは `bind` の書き方を示すための例です。具象クラスだけに依存するなら、同じ節にあるとおり結合は不要です。教材と食い違っているわけではありません。

## どこに書くか

| 場合 | すること |
| --- | --- |
| 具象クラスだけに依存する | 何も書かない（自動で作られる） |
| インターフェースを受け取る | どの実装を渡すかを登録する（この章の後のレッスンで扱う） |
| `string` や `int` などの値を受け取る | 渡す値をコンテナに教える |

値を受け取る場合は、文脈に応じた結合か、属性を使います。文脈に応じた結合では、`giveConfig` で設定の値を渡せます。

```php
$this->app->when(MapClient::class)
    ->needs('$region')
    ->giveConfig('services.map.region');
```

同じことを、クラスの側に属性で書くこともできます。

```php
use Illuminate\Container\Attributes\Config;

class MapClient
{
    public function __construct(
        #[Config('services.map.region')] private string $region,
    ) {}
}
```

`#[Config(...)]` を付けると、コンテナはその設定の値を渡します。

## 良い例と悪い例

悪い例: 具象クラスの組み立てを手で書く。

```php
$this->app->bind(ReportService::class, function (Application $app) {
    return new ReportService(
        $app->make(PdfRenderer::class),
        $app->make(ChartBuilder::class),
    );
});
```

なぜ悪いか: 自動で作れるものを手で書いているだけです。依存が増えたときに、ここを直し忘れると動かなくなります。

良い例: 何も書かず、コンストラクタの型宣言に任せる。

## AIが書きがちな誤り

- 具象クラスのたびに、サービスプロバイダに `bind` を書き足す
- メソッドの中で `app(ReportService::class)` のようにコンテナから取り出す。コンストラクタや引数で受け取れる場面なら、受け取るほうが依存が見えやすい（一般的な考え方）
- 設定の値が必要なクラスで、コンストラクタの中で `config()` を呼ぶ。動きはするが、受け取る値がコンストラクタの型から見えなくなる（一般的な考え方）

サービスプロバイダに結合を見つけたら、「これはインターフェースか、値を渡すためのものか」を確かめましょう。どちらでもなければ、不要な可能性があります。

## まとめ

- コンテナはコンストラクタの型宣言をたどって、依存を自動で作る
- 具象クラスだけに依存するクラスは、結合を書かなくてよい
- 結合が必要なのは、インターフェースや `string` などの値を受け取るとき
- 値は文脈に応じた結合や `#[Config]` などの属性で渡す
