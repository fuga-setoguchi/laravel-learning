## 演習の進め方

このレッスンでは、AIが書いた掲示板のコメントの検索と編集の機能をレビューします。ふつうに使う限り、正しく動きます。

使う知識は、次の章で扱ったものです。

| 章 | 主な観点 |
| --- | --- |
| 第8章 | 検証の規則、認可を確かめる場所 |
| 第11章 | マスアサインメント、CSRF、XSS、認可漏れ、SQL インジェクション |

セキュリティの問題は、ふつうに使っていても見つかりません。「攻撃者がログインして、URL やフォームの値を自由に書き換えて送ったら」と考えながら、利用者の入力がどこを通るかを追いましょう。

## レビュー対象のコード

```php
// bootstrap/app.php（抜粋）
->withMiddleware(function (Middleware $middleware): void {
    // フォームの送信で 419 になるので、コメントのルートを除外する
    $middleware->preventRequestForgery(except: ['comments/*']);
})

// app/Models/Comment.php
class Comment extends Model
{
    protected $guarded = [];
}

// routes/web.php（どちらも auth ミドルウェアだけ）
Route::get('/comments', [CommentController::class, 'index'])->middleware('auth');
Route::put('/comments/{comment}', [CommentController::class, 'update'])->middleware('auth');

// CommentController
public function index(Request $request)
{
    $comments = DB::select(
        "select * from comments where body like '%" . $request->input('q') . "%'"
    );

    return view('comments.index', ['comments' => $comments]);
}

public function update(Request $request, Comment $comment)
{
    $comment->update($request->all());

    return to_route('comments.index');
}

{{-- resources/views/comments/index.blade.php の @foreach の中 --}}
{!! $comment->body !!}
```

## 見つけるべき問題

**1. 他人のコメントを編集できる（第11章・第8章）**

`auth` ミドルウェアとルートモデル結合は、コメントの持ち主を確かめません。Policy に `update` を書き、ルートに `can('update', 'comment')` を付けます。

**2. 検索の SQL に入力を埋め込んでいる（第11章）**

キーワードにシングルクォートと SQL を書けば、条件を書き換えて、ほかのテーブルのデータも取り出せます。クエリビルダーの `where` で書けば、値はバインドされます。

**3. どの列でも書き換えられる（第11章・第8章）**

`$guarded = []` と `all()` の組み合わせで、`user_id` を足して送れば、コメントを他人の名前に付け替えられます。代入してよい列を決め、FormRequest で検証した値だけを渡します。

**4. コメントをエスケープせずに表示している（第11章）**

コメントに JavaScript を書けば、一覧を開いたほかの利用者のブラウザで動きます。`{{ }}` で表示します。

**5. コメントのルートを CSRF の確認から外している（第11章）**

419 を消すために除外すると、悪意のあるサイトから、ログイン中の利用者にコメントを書き換えさせられます。除外を戻し、フォームに `@csrf` を書きます。

5つの問題は、どれも「1か所の確かめ忘れ」で起きます。Laravel の守りは、既定では効いています（`{{ }}` のエスケープ、CSRF の確認、クエリビルダーのバインド）。AIのコードでは、その守りを外しているところ（`{!! !!}`、`except`、生の SQL、`$guarded = []`）と、そもそも守りがないところ（認可）を探すと、効率よく見つけられます（一般的な考え方）。

## 直したコード

```php
// bootstrap/app.php：comments/* の除外を消す（フォームには @csrf を書く）

// app/Models/Comment.php
#[Fillable(['body'])]
class Comment extends Model {}

// routes/web.php
Route::put('/comments/{comment}', [CommentController::class, 'update'])
    ->middleware('auth')
    ->can('update', 'comment');

// CommentController
public function index(Request $request)
{
    $comments = Comment::where('body', 'like', '%' . $request->input('q') . '%')
        ->latest()
        ->paginate(20);

    return view('comments.index', ['comments' => $comments]);
}

public function update(UpdateCommentRequest $request, Comment $comment)
{
    $comment->update($request->validated());

    return to_route('comments.index');
}
```

## まとめ

セキュリティをレビューするときは、次を確かめます。

- id を受け取る処理で、持ち主を確かめているか（第11章・第8章）
- 生の SQL や raw のメソッドに、入力を埋め込んでいないか（第11章）
- 代入してよい列を決め、検証済みの値だけを保存しているか（第11章・第8章）
- `{!! !!}` や CSRF の除外のように、Laravel の守りを外しているところはないか（第11章）
- 「攻撃者がログインして、値を書き換えて送ったら」と考えたか
