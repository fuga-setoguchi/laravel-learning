## 概念

**ルートグループ**は、複数のルートに共通の設定をまとめて付ける書き方です。

```php
Route::middleware(['auth'])
    ->prefix('admin')
    ->name('admin.')
    ->group(function () {
        Route::get('/users', [UserController::class, 'index'])->name('users.index');
    });
```

| まとめる設定 | 書き方 | 上の例での結果 |
| --- | --- | --- |
| ミドルウェア | `middleware([...])` | `auth` が付く |
| URL の接頭辞 | `prefix('admin')` | URL が `/admin/users` |
| 名前の接頭辞 | `name('admin.')` | 名前が `admin.users.index` |

名前の接頭辞はそのままつながるので、公式ドキュメントのとおり末尾にドットを付けます。グループを入れ子にすると、ミドルウェアは外側と内側の両方が付き、名前と URL の接頭辞は外側の後ろに内側がつながります。

Laravel には、ルートのファイルが用途別にあります。

| ファイル | 付くミドルウェアグループ | URL |
| --- | --- | --- |
| `routes/web.php` | web（セッション、CSRF の検証など） | そのまま |
| `routes/api.php` | api（セッションを使わない） | 自動で `/api` が付く |

公式ドキュメントは、`routes/api.php` のルートは状態を持たない（stateless）と説明しています。第2章で扱ったとおり、新規アプリに `routes/api.php` はなく、`install:api` で追加します。

## なぜ必要か

同じミドルウェアをルートごとに書くと、新しいルートを足したときに書き忘れやすくなります。管理画面のルートに `auth` を付け忘れれば、だれでも見られるページができます。グループにまとめれば、グループの中に書いたルートには必ず同じ設定が付きます。

web と api を分けるのは、使い方が違うからです。画面のアプリはセッションでログイン状態を保ち、フォームの送信を CSRF トークンで守ります。API は、ほかのアプリなどからの呼び出しを受け、セッションを使いません。

## どこに書くか

| ルート | 置き場所 |
| --- | --- |
| ブラウザで見る画面、フォームの送信先 | `routes/web.php` |
| 外部のアプリなどに提供する API | `routes/api.php`（必要になってから `install:api` で追加） |
| 同じ設定を付けたいルートの集まり | ルートグループの中 |

画面だけのアプリに、使う予定のない API のルートを足さないようにします。入口が増えるほど、確かめる範囲も増えるからです（一般的な考え方）。

## 良い例と悪い例

悪い例: 管理画面のルートを、グループの外に足す。

```php
Route::get('/admin/reports', [ReportController::class, 'index'])
    ->name('admin.reports.index');
```

なぜ悪いか: URL と名前は管理画面に見えても、グループのミドルウェアが付かないので、だれでも見られます。

良い例: グループの中に足す。

```php
Route::middleware(['auth'])->prefix('admin')->name('admin.')->group(function () {
    Route::get('/reports', [ReportController::class, 'index'])->name('reports.index');
});
```

## AIが書きがちな誤り

- 既存のグループの外に、同じ種類のルートを足す（ミドルウェアが付かない）
- `routes/api.php` の中で `prefix('api')` を重ね、URL が `/api/api/...` になる
- 名前の接頭辞の末尾のドットを書き忘れる
- 画面のフォームの送信先を `routes/api.php` に書く、または画面だけのアプリに API のルートを足す

ルートを足すコードを見たら、「同じ仲間のルートと同じグループに入っているか」を確かめましょう。

## まとめ

- ルートグループで、ミドルウェア・URL の接頭辞・名前の接頭辞をまとめて付けられる
- グループにまとめれば、ルートごとの設定漏れを防げる
- `routes/web.php` は画面用（セッション・CSRF）、`routes/api.php` は状態を持たない API 用で、自動で `/api` が付く
- API のルートは必要になってから追加する（一般的な考え方）
