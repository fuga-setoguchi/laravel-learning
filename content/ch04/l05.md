## 概念

**レート制限**は、一定の時間に受け付けるリクエストの回数を制限する仕組みです。上限を超えると、公式ドキュメントのとおり、Laravel は自動で 429（Too Many Requests）のレスポンスを返します。

レート制限は、`AppServiceProvider` の `boot` で名前を付けて定義します。

```php
use Illuminate\Cache\RateLimiting\Limit;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\RateLimiter;

RateLimiter::for('api', function (Request $request) {
    return Limit::perMinute(60)->by($request->user()?->id ?: $request->ip());
});
```

定義したレート制限は、`throttle` ミドルウェアでルートやグループに付けます。

```php
Route::middleware(['throttle:api'])->group(function () {
    // ...
});
```

`by()` は、回数を数える単位です。上の例では、ログインしている利用者はユーザーの id ごとに、していない人は IP アドレスごとに、1分に60回まで受け付けます。

## なぜ必要か

ログインの画面は、パスワードを次々に試す総当たりの攻撃を受けます。回数を制限しなければ、時間さえかければ試し続けられます。API でも、短い時間に大量に呼ばれると、アプリや、その先の外部のサービスに負担がかかります。

公式ドキュメントによると、`routes/api.php` に付く既定の api ミドルウェアグループには、レート制限は含まれていません。必要なルートには、自分で付けます。

## どこに書くか

数える単位の選び方は、一般的な考え方です（公式ドキュメントの例も参考にしています）。

| 対象 | 数える単位（by） |
| --- | --- |
| ログインしている利用者 | ユーザーの id |
| ログインしていない人 | IP アドレス |
| ログインの試行 | メールアドレス（公式ドキュメントの例）。IP アドレスと組み合わせることも多い |

IP アドレスだけで数えると、同じネットワークを共有する人がまとめて制限されます。逆に、リクエストの入力の値（`user_id` など）で数えると、送る側が値を変えるだけで制限を回避できます。数える単位には、送る側が自由に変えられない値を使います。

公式ドキュメントでは、複数の制限を配列で返す方法も紹介されています。ログインの例では、全体で1分に500回、メールアドレスごとに1分に3回までとしています。

## 良い例と悪い例

悪い例: 数える単位を決めない。

```php
RateLimiter::for('login', function (Request $request) {
    return Limit::perMinute(5);
});
```

なぜ悪いか: すべてのリクエストが1つの回数を共有します（Laravel 本体の実装による動き）。だれか1人が5回失敗すると、ほかの人もログインできなくなります。

良い例: アカウントと接続元の組み合わせで数える。

```php
RateLimiter::for('login', function (Request $request) {
    return Limit::perMinute(5)->by($request->input('email').'|'.$request->ip());
});
```

## AIが書きがちな誤り

- `by()` を付けずに `Limit::perMinute()` だけを返す
- リクエストの入力の値（`user_id` など）を数える単位にする
- ログインや API のルートに、`throttle` を付け忘れる
- レート制限を `register` に書く（公式ドキュメントでは `boot`）

レート制限を見つけたら、「何を単位に数えているか」「その値は送る側が変えられないか」を確かめましょう。

## まとめ

- レート制限は、一定の時間に受け付ける回数を制限する。超えると 429 が返る
- `AppServiceProvider` の `boot` で `RateLimiter::for()` で定義し、`throttle:名前` でルートに付ける
- `by()` で数える単位を決める。ログイン中はユーザーの id、それ以外は IP アドレスが基本
- api のルートにも、レート制限は自動では付かない
