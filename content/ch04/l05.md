## 概念

**レート制限**は、一定の時間に受け付けるリクエストの回数を制限する仕組みです。上限を超えると、公式ドキュメントのとおり、Laravel は自動で 429（Too Many Requests）のレスポンスを返します。

レート制限は、`AppServiceProvider` の `boot` で名前を付けて定義します。

```php
use Illuminate\Cache\RateLimiting\Limit;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\RateLimiter;

RateLimiter::for('api', function (Request $request) {
    return Limit::perMinute(60)->by($request->user()?->id ?: $request->ip());
});
```

定義したレート制限は、`throttle` ミドルウェアでルートやグループに付けます。

```php
Route::middleware(['throttle:api'])->group(function () {
    // ...
});
```

`by()` は、回数を数える単位です。上の例では、ログインしている利用者はユーザーの id ごとに、していない人は IP アドレスごとに、1分に60回まで受け付けます。

## なぜ必要か

ログインの画面は、パスワードを次々に試す総当たりの攻撃を受けます。回数を制限しなければ、時間さえかければ試し続けられます。API でも、短い時間に大量に呼ばれると、アプリや、その先の外部のサービスに負担がかかります。

公式ドキュメントによると、`routes/api.php` に付く既定の api ミドルウェアグループには、レート制限は含まれていません。必要なルートには、自分で付けます。

## どこに書くか

数える単位は、何を守りたいかで選びます。選び方は一般的な考え方です（公式ドキュメントの例も参考にしています）。

| 目的 | 数える単位（by） |
| --- | --- |
| 利用者ごとに使いすぎを防ぐ | ログイン中はユーザーの id、それ以外は IP アドレス |
| 1つのアカウントへの総当たりを防ぐ | メールアドレス（公式ドキュメントのログインの例） |
| 多くのアカウントを次々に試す攻撃を防ぐ | IP アドレスごとや、全体の制限を組み合わせる |
| アプリ全体の上限を決める | `by()` を付けない（公式ドキュメントの global の例） |

利用者ごとに数えたいときは、送る側が自由に変えられない値を使います。リクエストの入力の値（`user_id` など）で数えると、値を変えるだけで別の人として数えられ、制限を回避されます。IP アドレスだけで数えると、同じネットワークを共有する人がまとめて制限されます。

ログインでメールアドレスを使うのは、入力の値でも目的が違うからです。狙われた1つのアカウントを守るための制限なので、メールアドレスを変えれば、それは別のアカウントへの攻撃になります。そのアカウントへの試行は止められます。ただし、多くのアカウントを1回ずつ試す攻撃は、メールアドレスごとの制限では止まりません。IP アドレスごとや全体の制限と組み合わせます。

公式ドキュメントでは、複数の制限を配列で返す方法も紹介されています。ログインの例では、全体で1分に500回と、メールアドレスごとに1分に3回の制限を組み合わせています。同じ値を `by()` に渡す制限が複数あるときは、`'minute:'.$id` と `'day:'.$id` のように接頭辞を付けて、値を一意にするよう書かれています。

## 良い例と悪い例

悪い例: 数える単位を決めない。

```php
RateLimiter::for('login', function (Request $request) {
    return Limit::perMinute(5);
});
```

なぜ悪いか: `by()` なしは、アプリ全体で1つの上限を設ける書き方です。すべてのリクエストが1つの回数を共有するので（Laravel 本体の実装で確認した動き）、だれか1人が5回失敗すると、ほかの人もログインできなくなります。

良い例: アカウントごとの制限と、接続元ごとの制限を組み合わせる。

```php
use Illuminate\Support\Str;

RateLimiter::for('login', function (Request $request) {
    $email = Str::lower((string) $request->input('email'));

    return [
        Limit::perMinute(5)->by('email:'.$email),
        Limit::perMinute(20)->by('ip:'.$request->ip()),
    ];
});
```

メールアドレスは小文字にそろえてから使います。そろえないと、`Taro@example.com` と `taro@example.com` が別の値として数えられ、大文字・小文字を変えるだけで制限を回避されます（一般的な考え方）。

## AIが書きがちな誤り

- 利用者ごとに制限したい場面で、`by()` を付け忘れる
- 利用者ごとに数えたいのに、リクエストの入力の値（`user_id` など）を数える単位にする
- ログインの制限を、メールアドレスごとの制限だけにする
- ログインや API のルートに、`throttle` を付け忘れる
- レート制限を `register` に書く（公式ドキュメントでは `boot`）

レート制限を見つけたら、「何を守るための制限か」「その目的に合った単位で数えているか」を確かめましょう。

## まとめ

- レート制限は、一定の時間に受け付ける回数を制限する。超えると 429 が返る
- `AppServiceProvider` の `boot` で `RateLimiter::for()` で定義し、`throttle:名前` でルートに付ける
- `by()` で数える単位を決める。利用者ごとならユーザーの id や IP アドレスなど送る側が変えられない値、ログインの総当たり対策ならメールアドレスに IP アドレスごとの制限を組み合わせる
- api のルートにも、レート制限は自動では付かない
