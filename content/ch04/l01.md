## 概念

**ルート**は、「どの HTTP メソッドと URL のリクエストを、どの処理に渡すか」の対応です。Web の画面のルートは `routes/web.php` に書きます。

```php
use App\Http\Controllers\OrderController;

Route::get('/orders/{order}', [OrderController::class, 'show'])->name('orders.show');
Route::post('/orders', [OrderController::class, 'store'])->name('orders.store');
```

ルートには `->name()` で名前を付けられます。これを**名前付きルート**と呼びます。名前を付けておくと、URL を文字列で書かずに、名前から URL やリダイレクトを作れます。

```php
// URL を作る（ビューのリンクなど）
route('orders.show', ['order' => $order]);

// リダイレクトする（コントローラーなど）
return to_route('orders.show', ['order' => $order]);
```

公式ドキュメントによると、`route()` にはモデルをそのまま渡せて、モデルのルートキー（ふつうは主キー）が取り出されます。

## なぜ必要か

ルートのファイルは、アプリが受け付ける URL の一覧でもあります。ここに処理を書き込むと、一覧が処理に埋もれ、どの URL があるかを読み取りにくくなります。処理はコントローラーに置き、ルートには対応だけを書きます（一般的な考え方）。公式ドキュメントの例にはクロージャのルートもありますが、これはルートの書き方を示すためのものです。

URL を直接書かない理由は、変更に強くするためです。`'/orders/' . $order->id` のように書いた箇所は、URL の形を変えるとすべて直す必要があります。名前で指定していれば、ルートの定義を1か所直すだけで、新しい URL が作られます（これは公式ドキュメントの記載ではなく、一般的な考え方です。公式ドキュメントは、名前付きルートで URL やリダイレクトを手軽に作れると説明しています）。

## どこに書くか

| 書くもの | 置き場所 |
| --- | --- |
| URL と処理の対応、ルートの名前 | `routes/web.php` |
| リクエストを受けてからの処理 | コントローラー（第5章で扱う） |
| リンクの URL | ビューで `route('名前', [...])` |
| リダイレクト先 | コントローラーで `to_route('名前', [...])` または `redirect()->route(...)` |

名前は `orders.show` のように「対象.操作」の形にそろえると、一覧で見つけやすくなります（一般的な考え方）。公式ドキュメントは、ルートの名前は常に一意にするよう求めています。

登録されているルートは、`php artisan route:list` で一覧にできます。

## 良い例と悪い例

悪い例: ルートに処理を書き、URL も直接書く。

```php
Route::post('/orders', function (Request $request) {
    $order = Order::create($request->validate([/* ... */]));
    // 在庫の更新、メール送信 ...
    return redirect('/orders/' . $order->id);
});
```

なぜ悪いか: URL の一覧が処理に埋もれます。リダイレクト先の URL を変えると、この行も直す必要があります。

良い例: ルートには対応と名前だけを書き、処理はコントローラーで行う。

```php
Route::post('/orders', [OrderController::class, 'store'])->name('orders.store');

// OrderController
return to_route('orders.show', ['order' => $order]);
```

## AIが書きがちな誤り

- `href="/orders/{{ $order->id }}"` や `redirect('/orders/' . $order->id)` のように、URL を文字列で組み立てる
- ルートのクロージャに、保存や外部サービスの呼び出しなどの処理を書き込む
- コピーしたルートの `->name()` を直し忘れ、名前が重複する

ビューやコントローラーに `/` で始まる URL の文字列を見つけたら、「名前付きルートで書けないか」を確かめましょう。

## まとめ

- ルートのファイルには、URL と処理の対応だけを書く。処理はコントローラーに置く
- ルートに `->name()` で名前を付け、URL は `route()`、リダイレクトは `to_route()` で作る
- 名前で指定すれば、URL を変えても呼び出す側を直さずに済む
- ルートの名前は一意にする
