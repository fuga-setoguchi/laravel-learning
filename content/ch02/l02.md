## 概念

第1章で、モデル・ビュー・コントローラーの置き場所を扱いました。このレッスンでは、それ以外のクラスをどこに置くかを考えます。

Laravel 13 の新規アプリの `app` フォルダには、最初は次の3つだけがあります。

| フォルダ | 入るもの |
| --- | --- |
| `app/Http` | コントローラー、ミドルウェア、フォームリクエスト |
| `app/Models` | Eloquent のモデル |
| `app/Providers` | サービスプロバイダ（最初は `AppServiceProvider`） |

`Jobs`・`Events`・`Listeners`・`Mail`・`Policies`・`Rules`・`Console` などのフォルダは、最初はありません。`make:job` や `make:policy` などのコマンドを実行したときに作られます。

公式ドキュメントは、Composer が自動で読み込めるかぎり、クラスの置き場所にほとんど制限はないと説明しています。`app` の下は名前空間 `App` として読み込まれるので、自分で `app/Actions` を作れば、`App\Actions\...` のクラスとして使えます。

## なぜ必要か

置き場所が自由ということは、決めるのは自分たちだということです。決めずにいると、次のようなことが起きます。

- 「コントローラーから使うから」という理由で、計算のクラスが `app/Http/Controllers` に入る
- 同じ種類のクラスが、`app/Services`・`app/Helpers`・`app/Utils` にばらばらに置かれる

こうなると、フォルダを見ても役割がわからず、AIも既存のクラスを見つけられないまま、同じ処理を別の場所にもう一度書いてしまいます。

公式ドキュメントは、`Console` と `Http` のフォルダを、アプリの中心へ入るための入口（API）と考えるよう説明しています。HTTP やコマンドラインは、アプリに指示を出す手段であって、アプリのロジックそのものではありません。計算や業務のルールを `app/Http`（コントローラー）に置かないのは、このためです。

## どこに書くか

まず、Laravel の既定のフォルダに当てはまるかを考えます。ジョブなら `app/Jobs`、ポリシーなら `app/Policies` のように、make コマンドが作る場所に置きます。

既定のフォルダに当てはまらない、アプリ固有の処理が増えてきたら、役割を表す名前のフォルダを作ります。たとえば「1つのユースケースを実行するクラス」を `app/Actions` にまとめる、といった形です。これは公式ドキュメントの記載ではなく、一般的な考え方です。`Actions` などの名前も、Laravel が決めたものではありません。このクラスの作り方は、第5章で扱います。

| 判断 | 例 |
| --- | --- |
| 既定のフォルダに入るものはそこへ | ジョブ → `app/Jobs`、ポリシー → `app/Policies` |
| 入らないものは、役割の名前のフォルダを作る | ユースケース → `app/Actions` |
| 一度決めたら、同じ種類のクラスは同じ場所へ | `app/Services` と `app/Actions` を混ぜない |

## 良い例と悪い例

悪い例: 計算のクラスを、使う側の都合でコントローラーのフォルダに置く。

```php
// app/Http/Controllers/OrderTotalCalculator.php
namespace App\Http\Controllers;

class OrderTotalCalculator { /* ... */ }
```

なぜ悪いか: 動きはしますが、場所と名前空間から、コントローラーだと誤解されます。

良い例: 役割を表すフォルダに置く。

```php
// app/Actions/CalculateOrderTotal.php
namespace App\Actions;

class CalculateOrderTotal { /* ... */ }
```

## AIが書きがちな誤り

- コントローラーから使うクラスを、`app/Http/Controllers` に置く
- プロジェクトにすでに `app/Actions` があるのに、新しく `app/Services` を作って似たクラスを置く
- 新規アプリに `routes/api.php` があるものとして提案する（新規アプリでは `install:api` で追加する）
- `app/Console/Kernel.php` があるものとして、そこへの登録を提案する（新規アプリでは、定期実行するタスクは `routes/console.php` に定義する）

AIが新しいフォルダを作ったら、「既存のフォルダに同じ役割のものはないか」を確かめましょう。

## まとめ

- 新規アプリの `app` には `Http`・`Models`・`Providers` だけがあり、他のフォルダは make コマンドで作られる
- Composer が読み込める場所なら、クラスの置き場所はほとんど自由
- 置き場所は「どこから使うか」ではなく「クラスの役割」で決める
- 自分で作るフォルダ（`app/Actions` など）は一般的な考え方。一度決めたら同じ種類のクラスを同じ場所に置く
