## 概念

`php artisan config:cache` は、`config` フォルダのすべての設定ファイルを1つのファイルにまとめるコマンドです。リクエストのたびに多くの設定ファイルを読む必要がなくなり、起動が速くなります。

ただし、大きな副作用があります。設定をキャッシュすると、リクエストや Artisan コマンドの実行時に `.env` が読み込まれなくなります。そのため、`env()` はサーバーの環境変数しか返さなくなります。

キャッシュを消すときは `php artisan config:clear` を使います。

## なぜ必要か

前のレッスンで、設定ファイルの中で `env()` を使って `.env` の値を読むことを扱いました。ここで「なぜ `env()` を設定ファイルの中だけで使うのか」の理由がわかります。

- **設定ファイルの中の `env()`**: キャッシュを作るときに評価され、その結果がキャッシュに保存される。キャッシュした後も、正しい値が使われる（公式ドキュメントにこの仕組みの説明はないが、設定ファイルの中でだけ env() を呼ぶよう求めていることから、こう理解してよい）
- **コントローラーなどの `env()`**: リクエストのたびに呼ばれる。キャッシュした後は `.env` が読まれないので、`.env` にしかない値は返らない

公式ドキュメントも、`env()` は設定ファイルの中だけで呼ぶよう求めています。

もう1つの利点は、値の出どころが1か所にまとまることです。アプリのコードが `config('services.payment.key')` だけを読むようにしておけば、テストで `config(['services.payment.key' => 'test-key'])` のように値を差し替えることもできます。

厄介なのは、開発中は問題が見えないことです。公式ドキュメントは、開発中は設定をよく変えるので `config:cache` を実行しないよう勧めています。一方、本番のデプロイでは実行することが推奨されています。つまり、コントローラーに書いた `env()` は、開発中は動き、本番で初めて壊れます。

## どこに書くか

| やること | 置き場所 |
| --- | --- |
| `.env` の値を読む（`env()`） | `config` フォルダの設定ファイルの中だけ |
| 設定値を使う（`config()`） | コントローラー、サービス、ビューなど、アプリのコード |
| `config:cache` の実行 | 本番のデプロイの手順。開発中は実行しない |

## 良い例と悪い例

悪い例: コントローラーで `env()` を呼ぶ。

```php
$client->charge(
    amount: $request->integer('amount'),
    apiKey: env('PAYMENT_API_KEY'),
);
```

なぜ悪いか: 本番で設定をキャッシュすると、`env('PAYMENT_API_KEY')` は `null` を返し、決済が失敗します。

良い例: 設定ファイルで読み、コードでは `config()` を使う。

```php
// config/services.php
'payment' => [
    'key' => env('PAYMENT_API_KEY'),
],

// コントローラー
$client->charge(
    amount: $request->integer('amount'),
    apiKey: config('services.payment.key'),
);
```

## AIが書きがちな誤り

- コントローラーやサービスのクラスで `env()` を直接呼ぶ。開発中はテストも画面も通るので、気づきにくい
- 「.env を変えたのに反映されない」という相談に対して、`config:cache` をもう一度実行するよう勧める（開発中は `config:clear` で消すのが先）
- 開発環境の手順に `config:cache` を入れる
- 開発中に、高速化のために `php artisan optimize` を勧める（`optimize` は設定・イベント・ルート・ビューをまとめてキャッシュするので、`config:cache` も実行される。消すときは `optimize:clear`）

コードの中に `env(` を見つけたら、それが `config` フォルダの中かどうかを確かめましょう。

## まとめ

- `config:cache` は設定を1つのファイルにまとめて速くするが、`.env` が読まれなくなる
- そのため `env()` は設定ファイルの中だけで使い、アプリのコードでは `config()` を使う
- 設定のキャッシュは本番のデプロイで使い、開発中は使わない（消すときは `config:clear`）
- コントローラーの `env()` は、開発中は動いて本番で壊れる
