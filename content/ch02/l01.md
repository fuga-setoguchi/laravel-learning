## 概念

Laravel の新規アプリには、役割ごとに分かれたフォルダがあります。主なものは次のとおりです。

| フォルダ | 入るもの |
| --- | --- |
| `app` | アプリの中心となるコード（コントローラー、モデル、サービスプロバイダなど） |
| `bootstrap` | フレームワークを起動する `app.php` と、高速化のためにフレームワークが生成するキャッシュ（`bootstrap/cache`） |
| `config` | 設定ファイル |
| `database` | マイグレーション、モデルファクトリ、シーダー |
| `public` | すべてのリクエストの入口 `index.php` と、画像・CSS・JavaScript などの公開するファイル |
| `resources` | Blade のビューと、コンパイル前の CSS・JavaScript |
| `routes` | ルートの定義（新規アプリには `web.php` と `console.php`） |
| `storage` | 実行中にアプリが書き込むもの。`app`・`framework`・`logs` に分かれる |
| `tests` | 自動テスト |
| `vendor` | Composer でインストールしたパッケージ |

この中で、Web サーバーが外に公開するのは `public` だけです。

## なぜ必要か

置き場所が決まっていると、どこに何があるかを探さずに済みます。AIが「このファイルを作りました」と言ったときも、その場所を見ただけで役割の見当がつきます。

特に大切なのは、「公開する場所」と「公開しない場所」の区別です。公式ドキュメントのデプロイの章は、`index.php` をプロジェクトのルートに移してはいけないと書いています。プロジェクトのルートから配信すると、機密情報を含む設定ファイルがインターネットに公開されてしまうためです。`.env` にはデータベースのパスワードや外部サービスの鍵が入っています。これが URL で取得できたら、アプリ全体が危険にさらされます。

## どこに書くか

- **公開してよいもの**（ビルド済みの CSS、ロゴ画像など）は `public`
- **ビューやコンパイル前の CSS・JavaScript** は `resources`。ここは直接公開されない
- **利用者がアップロードした公開用のファイル** は `storage/app/public`。`php artisan storage:link` で `public/storage` からのリンクを作って公開する
- **ログやキャッシュなど、アプリが書き込むもの** は `storage`。`storage/app/public` 以外は公開しない
- **`bootstrap/cache`** はフレームワークが生成するファイルの置き場

## 良い例と悪い例

悪い例: 書き出したファイルを `public` の下に置く。

```php
file_put_contents(public_path('exports/users.csv'), $csv);
return redirect('/exports/users.csv');
```

なぜ悪いか: `public` の下のファイルは Web サーバーがそのまま配信し、ログインや権限の確認を通りません。URL を推測できれば、誰でも会員の情報を取得できます。

良い例: 公開しない場所に保存し、権限を確かめてからダウンロードさせる。

```php
// storage の公開しない場所に保存し、権限を確かめたうえで返す
$path = storage_path('app/exports/users.csv');
file_put_contents($path, $csv);

return response()->download($path);
```

（権限の確かめ方は第8章で扱います。）

## AIが書きがちな誤り

- アップロードされたファイルや書き出したファイルを、`public_path()` の下に直接保存する
- 共用サーバー向けの説明として、`index.php` をプロジェクトのルートに移す方法を提案する
- コンパイル前の CSS や JavaScript を `public` に置き、`resources` との役割を混ぜる

ファイルを保存するコードを見たら、まず「その場所は URL で取得できるか」を確かめましょう。

## まとめ

- 公開するのは `public` だけ。入口の `index.php` と、そのまま配信してよいファイルを置く
- プロジェクトのルートを公開すると、`.env` などの機密情報が漏れる
- `resources` は元になるファイル、`storage` は実行中に書き込むもの、`bootstrap/cache` はフレームワークのキャッシュ
- 利用者のファイルを公開するときは `storage/app/public` と `storage:link` を使う
