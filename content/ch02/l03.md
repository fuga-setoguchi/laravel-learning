## 概念

Laravel の設定は、2つの場所に分かれています。

| 場所 | 役割 | コミット |
| --- | --- | --- |
| `.env` | 環境（自分の PC、本番のサーバーなど）ごとに変わる値 | しない |
| `config/*.php` | アプリが使う設定の一覧。値を `.env` から読むか、既定値を使うかを決める | する |

新規アプリには `.env.example` があり、インストール時に `.env` にコピーされます。

`.env` の値は、サーバーやシステムに設定された環境変数があれば、そちらで上書きされます。つまり、同じ名前の環境変数がサーバーにあれば、`.env` よりもそちらが優先されます。`.env.example` は「どんな値が必要か」を示すひな形で、コミットします。

設定ファイルでは、`env()` で `.env` の値を読みます。第2引数は、その環境変数がないときの既定値です。

```php
// config/app.php の一部
'debug' => (bool) env('APP_DEBUG', false),
```

`.env` の値は文字列ですが、`true`・`false`・`null`・`empty` と書くと、それぞれ真偽値・null・空文字として読まれます。空白を含む値は `APP_NAME="My Application"` のように二重引用符で囲みます。

アプリのコードからは、`config()` ヘルパーで設定値を読みます。ファイル名とキーをドットでつなぎます。

```php
$timezone = config('app.timezone');
$timeout = config('services.payment.timeout', 10); // 第2引数は既定値
```

型が決まっている値は、`Config::integer('services.payment.timeout')` のように型を指定して読むこともできます。値の型が違えば例外になるので、設定の誤りに早く気づけます。

## なぜ必要か

同じコードを、開発中の PC と本番のサーバーで動かすためです。データベースの接続先や外部サービスの鍵は、環境ごとに違います。これらをコードに直接書くと、環境ごとにコードを書き換えることになります。

`.env` をコミットしない理由は、公式ドキュメントによると2つあります。開発者やサーバーごとに必要な値が違うこと、そしてリポジトリが漏れたときに機密情報まで漏れてしまうことです。

## どこに書くか

| 値の種類 | 置き場所 |
| --- | --- |
| パスワード、API の鍵 | `.env`（`.env.example` には空欄で書く） |
| 環境ごとに変わる値（接続先、デバッグの有無） | `.env` |
| どの環境でも同じ値（タイムアウトの秒数など） | `config` のファイルに直接書いてよい |
| アプリが値を読むところ | `config()` |

新しい設定を足すときは、`config` のファイルにキーを追加し、環境ごとに変わる部分だけを `env()` で `.env` から読むようにします。

## 良い例と悪い例

悪い例: 本番の鍵を、設定ファイルに直接書く。

```php
// config/services.php
'payment' => [
    'secret' => 'prod-secret-value',
],
```

なぜ悪いか: `config` のファイルはコミットされるので、鍵がリポジトリに残ります。開発用と本番用で鍵を変えることもできません。

良い例: 値は `.env` に置き、設定ファイルから読む。

```php
// config/services.php
'payment' => [
    'secret' => env('PAYMENT_SECRET'),
],
```

`.env.example` には `PAYMENT_SECRET=` と空欄で書き、必要な環境変数があることを示します。

## AIが書きがちな誤り

- 動作確認のために、鍵やパスワードを設定ファイルやコードに直接書く
- 新しい環境変数を `.env` に追加したのに、`.env.example` に書き足さない（他の人の環境で動かない）
- 暗号化していない `.env` を Git の管理に入れるよう提案する（`php artisan env:encrypt` で暗号化したファイルなら、コミットしても安全とされている）

設定値を扱うコードを見たら、「その値は環境ごとに変わるか」「機密か」を確かめましょう。

## まとめ

- `.env` は環境ごとに変わる値、`config` はアプリが使う設定の一覧
- `.env` はコミットしない。必要な値は `.env.example` にひな形として書く
- 機密の値は設定ファイルに直接書かず、`.env` に置いて `env()` で読む
- アプリのコードからは `config('ファイル名.キー')` で読む
