## 概念

公式ドキュメントは、Eloquent を ORM（オブジェクトとリレーショナルデータベースを対応させる仕組み）と説明しています。各テーブルには対応するモデルがあり、モデルを通してテーブルの行を取り出したり、作成・更新・削除したりします。

```php
$post = Post::find(1);           // 1行を取り出す
$post->title = '新しいタイトル';
$post->save();                   // 自分自身を保存する
```

このように、1つのオブジェクトがテーブルの1行のデータと、自分を保存・削除する処理の両方を持つ設計を、一般に **Active Record** と呼びます。Active Record は公式ドキュメントの用語ではなく、一般的な設計の用語です。

## なぜ必要か

Active Record の長所と短所は、一般的な考え方です。

**長所**: 少ないコードで読み書きができます。`Post` というクラスを作れば、規約で `posts` テーブルと結び付き、取り出し・作成・更新・削除のメソッドがすぐに使えます。テーブルの名前などを変えたいときも、モデルに `#[Table('...')]` 属性を付けるだけです。

**短所**: モデルに何でも書けてしまうことです。データを持ち、データベースにも触れるので、「注文のことなら Order に書こう」と、決済・在庫・通知・表示の加工までがモデルに集まりがちです。モデルが数百行になると、どこに何があるかわからなくなり、変更の影響も読みにくくなります。モデルのメソッドがデータベースに触れるので、テストにもデータベースが必要になりやすくなります。

Active Record と対になる設計として、データを持つオブジェクトと、保存を行うクラス（リポジトリなど）を分ける設計もあります。Eloquent は Active Record の側なので、その長所を生かしつつ、短所は「何をモデルに置くか」の工夫で補います（一般的な考え方）。

## どこに書くか

肥大を防ぐには、モデルに置くものを絞ります。見分け方は一般的な考え方です。

| 処理 | 置き場所 |
| --- | --- |
| 列の型の変換（日時・列挙型など） | モデルのキャスト（この章の次のレッスン） |
| よく使う検索条件 | モデルのクエリスコープ（この章で扱う） |
| テーブルどうしの関係 | モデルのリレーション（第7章） |
| 複数のモデルや外部サービスにまたがる手順 | Action などのクラス（第5章） |

モデルには「そのテーブルのデータがどんな性質を持つか」を置き、「データを使って何をするか」という手順は外に出す、と考えると見分けやすくなります。

## 良い例と悪い例

悪い例: 注文の確定の手順をモデルに書く。

```php
class Order extends Model
{
    public function checkout(PaymentGateway $gateway): void
    {
        // 決済、在庫の更新、状態の更新、メール送信 ...
    }
}
```

なぜ悪いか: モデルが外部サービスや別のモデルの処理まで抱え、肥大していきます。

良い例: 手順は Action に出し、モデルはデータの性質だけを持つ。

```php
class Order extends Model
{
    protected function casts(): array
    {
        return ['status' => OrderStatus::class, 'paid_at' => 'datetime'];
    }
}

// app/Actions/CheckoutOrder.php が決済・在庫・通知の手順を持つ
```

## AIが書きがちな誤り

- 「注文の処理だから」と、決済や通知の手順を Order のモデルに足していく
- 表示のための文字列の組み立て（HTML や文言）をモデルのメソッドに書く
- 逆に、キャストやスコープのようなモデルに置くべき処理まで、コントローラーに書く

モデルに新しいメソッドが足されたら、「これはこのテーブルのデータの性質か、それとも手順か」を確かめましょう。

## まとめ

- Eloquent のモデルは、データと、データベースへの読み書きを1つのオブジェクトに持つ（一般に Active Record と呼ぶ）
- 長所は、少ないコードで読み書きできること
- 短所は、何でも書けるので肥大しやすいこと
- モデルにはデータの性質（キャスト・スコープ・リレーション）を置き、手順は外に出す（一般的な考え方）
