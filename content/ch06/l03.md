## 概念

**キャスト**は、モデルの属性を取り出すときと保存するときに、決めた型に変換する設定です。13.x では、モデルの `casts()` メソッドが返す配列に書きます。

```php
class Post extends Model
{
    protected function casts(): array
    {
        return [
            'published_at' => 'datetime',      // Carbon のインスタンスになる
            'is_featured' => 'boolean',        // true / false になる
            'status' => PostStatus::class,     // 列挙型になる
            'options' => 'array',              // JSON の列が配列になる
        ];
    }
}
```

公式ドキュメントによると、Eloquent は `created_at` と `updated_at` を既定で Carbon に変換します。ほかの日時の列は、`datetime` などのキャストを書くと Carbon になります。

列挙型のキャストを使うと、値を列挙型で比べたり代入したりできます。

```php
if ($post->status === PostStatus::Published) {
    // ...
}

$post->status = PostStatus::Draft;
$post->save();
```

## なぜ必要か

キャストがないと、変換を使う場所ごとに書くことになります。コントローラーで `Carbon::parse()`、ビューで `(bool)`、ジョブでまた `Carbon::parse()` と、同じ変換が散らばり、書き忘れた場所で型がずれます。キャストに書けば、そのモデルをどこで使っても同じ型になります（一般的な考え方）。

列挙型のキャストは、状態の値の打ち間違いも防ぎます。`'published'` のような文字列で比べると、`'pubished'` と書き間違えても気づきにくいからです。

## どこに書くか

| 変換 | キャスト |
| --- | --- |
| 日時 | `datetime`（変更しない Carbon がよければ `immutable_datetime`） |
| 真偽値 | `boolean` |
| 状態などの決まった値 | 列挙型のクラス（`PostStatus::class`） |
| JSON の列 | `array`、`AsArrayObject::class`、`AsCollection::class` |

`array` にキャストした属性は、配列の一部だけを直接書き換えられません。公式ドキュメントのとおり、変数に取り出して書き換え、入れ直します。

```php
$settings = $user->settings;
$settings['theme'] = 'dark';
$user->settings = $settings;
$user->save();
```

公式ドキュメントによると、`date` と `datetime` のキャストは、モデルを JSON にするとき、アプリのタイムゾーンの設定に関係なく UTC の ISO-8601 形式で出力されます。

JSON にするときの形式を変えたいなら、`'datetime:Y-m-d H:i:s'` のように形式を指定します。形式を指定すると、タイムゾーンの扱いも変わり、Carbon が持つタイムゾーン（ふつうはアプリのタイムゾーン）で出力されます。ただし、`created_at` と `updated_at` のような `timestamp` の列は、形式を指定しても常に UTC で出力されます。公式ドキュメントは、アプリのタイムゾーンを既定の UTC のまま変えず、日時を UTC で保存することを強く勧めています。

キャストの形式は、JSON にするときのものです。画面に表示するときの形式は、ビューで `$post->published_at->format('Y/m/d')` のように決めます。

## 良い例と悪い例

悪い例: 使う場所で型を変換する。

```php
$post->published_at = Carbon::parse($post->published_at);
$post->is_featured = (bool) $post->is_featured;
```

なぜ悪いか: Post を使う場所ごとに同じ変換が必要になり、書き忘れた場所で型がずれます。

良い例: モデルの `casts()` に書く（「概念」のコードを参照）。

## AIが書きがちな誤り

- コントローラーやビューで、`Carbon::parse()` や `(bool)` をくり返す
- 状態の列を文字列のまま比べる（`$post->status === 'published'`）
- `array` にキャストした属性の一部を、`$user->settings['theme'] = ...` と直接書き換える

モデルの属性を変換しているコードを見たら、「この変換はキャストに書けないか」を確かめましょう。

## まとめ

- キャストは、属性を取り出すときと保存するときに型を変換する設定。`casts()` に書く
- 変換をモデルに1か所でまとめれば、使う場所ごとにくり返さずに済む
- 状態の列は列挙型にキャストし、列挙型の値で比べる
- `array` のキャストは、取り出して書き換えてから入れ直す
