## 概念

**クエリスコープ**は、検索条件に名前を付けてモデルに置く仕組みです。2種類あります。

**ローカルスコープ**は、呼んだときだけ条件が付きます。13.x では、モデルのメソッドに `#[Scope]` 属性を付けて書きます。

```php
use Illuminate\Database\Eloquent\Attributes\Scope;

class Post extends Model
{
    #[Scope]
    protected function published(Builder $query): void
    {
        $query->where('status', 'published')
            ->where('published_at', '<=', now());
    }

    #[Scope]
    protected function ofCategory(Builder $query, int $categoryId): void
    {
        $query->where('category_id', $categoryId);
    }
}

$posts = Post::published()->ofCategory(3)->latest()->get();
```

引数を受け取るスコープも作れます。

**グローバルスコープ**は、そのモデルへのすべての問い合わせに自動で条件が付きます。`php artisan make:scope` でクラスを作り、モデルに `#[ScopedBy([...])]` 属性で付けます。公式ドキュメントによると、Laravel のソフトデリートも、グローバルスコープで削除済みでない行だけに絞っています。

## なぜ必要か

同じ `where` の組み合わせがコントローラーごとに書かれていると、条件を変えたときに直し漏れが出ます。「公開済み」の意味が画面によってずれる、といった不具合になります。ローカルスコープに名前を付ければ、条件は1か所にまとまり、`Post::published()` という名前で意図も読み取れます。

グローバルスコープは便利な反面、問い合わせのコードに条件が見えません。`Post::where('status', 'draft')` と書いたのに、グローバルスコープの条件も付いて1件も返らない、ということが起きます。コードを読んだ人が気づきにくいのが注意点です。

## どこに書くか

ローカルとグローバルの選び方は、一般的な考え方です。

| 条件 | 選ぶもの |
| --- | --- |
| よく使うが、使わない場面もある（公開済み、カテゴリで絞るなど） | ローカルスコープ |
| ほぼすべての問い合わせで必ず付けたい（削除済みを除くなど） | グローバルスコープ |

迷ったらローカルスコープにします。グローバルスコープを外す場面が多いなら、ローカルスコープのほうが向いています。

スコープを `orWhere` と組み合わせるときは、条件のまとまりに注意します。SQL では AND が OR より先に結び付くので、`Post::published()->where('category_id', 3)->orWhere('is_pinned', true)` は「公開済みでカテゴリ3」または「ピン留め」になり、ピン留めされた下書きまで返ります（SQL の一般的な決まり）。OR でつなぐ部分は、クロージャでまとめます。

```php
$posts = Post::published()
    ->where(function (Builder $query) {
        $query->where('category_id', 3)->orWhere('is_pinned', true);
    })
    ->get();
```

公式ドキュメントは、スコープどうしを OR でつなぐとき、まとまりを正しく作るためにクロージャが必要になる場合があると説明し、その代わりに `Post::published()->orWhere->featured()` のような書き方もできるとしています。

グローバルスコープを外すには、`withoutGlobalScope(スコープのクラス)` を使います。すべて外すなら `withoutGlobalScopes()` です。

```php
$drafts = Post::withoutGlobalScope(PublishedScope::class)
    ->where('status', 'draft')
    ->get();
```

## 良い例と悪い例

悪い例: 同じ条件をコントローラーごとに書く。

```php
$posts = Post::where('status', 'published')
    ->where('published_at', '<=', now())
    ->latest()->paginate(20);
```

なぜ悪いか: 条件が変わったときに、書き写したすべての箇所を直す必要があります。

良い例: ローカルスコープに名前を付けて呼ぶ。

```php
$posts = Post::published()->latest()->paginate(20);
```

## AIが書きがちな誤り

- 同じ `where` の組み合わせを、コントローラーやジョブにくり返し書く
- 「公開済み」のように外す場面がある条件を、グローバルスコープにする
- グローバルスコープがあることを見落とし、管理画面などで絞られた結果のまま使う
- スコープの後に `orWhere` を素朴につなぎ、AND と OR のまとまりが崩れて、意図しない行まで返す

モデルの問い合わせが期待どおりの件数を返さないときは、「グローバルスコープが付いていないか」を確かめましょう。

## まとめ

- ローカルスコープは、よく使う条件に名前を付け、呼んだときだけ付ける
- グローバルスコープは、すべての問い合わせに自動で付く。コードに見えないので気づきにくい
- 迷ったらローカルスコープ。グローバルスコープは `withoutGlobalScope()` で外せる
- ソフトデリートもグローバルスコープで動いている
