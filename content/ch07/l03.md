## 概念

**トランザクション**は、複数の書き込みを1つのまとまりとして扱う仕組みです。まとまりの中の書き込みは、全部が成功して確定する（コミット）か、全部が取り消される（ロールバック）かのどちらかになります。

Laravel では、`DB::transaction()` にクロージャを渡します。

```php
use Illuminate\Support\Facades\DB;

$order = DB::transaction(function () use ($user, $items) {
    $order = $user->orders()->create(['status' => 'pending']);

    foreach ($items as $item) {
        $order->items()->create($item);
        Product::whereKey($item['product_id'])->decrement('stock', $item['qty']);
    }

    return $order;
});
```

公式ドキュメントによると、クロージャの中で例外が起きると、自動でロールバックされ、例外は投げ直されます。クロージャが成功すれば、自動でコミットされます。自分で `commit` や `rollBack` を書く必要はありません。DB ファサードのトランザクションは、クエリビルダーと Eloquent の両方の書き込みを扱います。

## なぜ必要か

注文の作成、明細の保存、在庫の更新のように、複数の書き込みがそろって初めて意味を持つ処理があります。途中で失敗すると、一部の書き込みだけが残り、「注文はあるのに明細がない」「在庫だけ減っている」といった食い違いが生まれます。食い違ったデータは、あとから直すのが大変です。トランザクションにまとめれば、失敗したときに最初の状態に戻ります。

## どこに書くか

| 場面 | 書き方 |
| --- | --- |
| 複数の書き込みをまとめる | `DB::transaction(function () { ... })` |
| デッドロックのときに再試行する | `DB::transaction(function () { ... }, attempts: 5)` |
| 開始と確定を自分で書く必要がある | `DB::beginTransaction()`、`DB::commit()`、`DB::rollBack()` |

ふつうはクロージャを渡す書き方を使います。コミットとロールバックの書き忘れが起きないからです（一般的な考え方）。

トランザクションの範囲には、注意点が2つあります（どちらも一般的な考え方）。

- **例外を中で受け止めない**: クロージャの中で例外を受け止めて投げ直さないと、クロージャは成功したことになり、途中までの書き込みがコミットされます。
- **取り消せない処理を入れない**: ロールバックで取り消せるのはデータベースの書き込みだけです。外部の決済 API の呼び出しや、送ったメールは取り消せません。こうした処理は、コミットの後に行うか、失敗したときの取り消し方を別に考えます。キューのジョブとトランザクションの関係は、第9章で扱います。

トランザクションだけでは足りない場面もあります。トランザクションが防ぐのは「途中で失敗して一部だけが残る」ことです。同時に来た2つの注文が、在庫を確認してから減らすまでの間に割り込み合う問題は、それだけでは防げません（一般的な考え方）。在庫を確認してから更新する処理では、`lockForUpdate()` などのロックが必要になります。公式ドキュメントは、ロックをトランザクションの中で使うことを勧めています。

## 良い例と悪い例

悪い例: 例外をクロージャの中で受け止める。

```php
DB::transaction(function () use ($user, $items) {
    try {
        // 注文と明細の作成
    } catch (Throwable $e) {
        Log::error('注文の作成に失敗しました');
    }
});
```

なぜ悪いか: クロージャが成功したことになり、途中までの書き込みがコミットされます。

良い例: 例外はクロージャの外で受け止める。

```php
try {
    DB::transaction(function () use ($user, $items) {
        // 注文と明細の作成
    });
} catch (Throwable $e) {
    Log::error('注文の作成に失敗しました');
    throw $e;
}
```

## AIが書きがちな誤り

- 複数の書き込みを、トランザクションにまとめずに並べる
- クロージャの中で例外を受け止め、ログに書くだけにする
- トランザクションの中で外部の API を呼び、ロールバックで取り消せると考える

複数の書き込みが並んでいるコードを見たら、「途中で失敗したら、どんな状態が残るか」を考えましょう。

## まとめ

- トランザクションは、複数の書き込みを「全部成功」か「全部取り消し」にする仕組み
- `DB::transaction()` は、成功すればコミット、例外ならロールバックして例外を投げ直す
- クロージャの中で例外を受け止めると、途中までの書き込みがコミットされる
- 外部の API やメールは、ロールバックで取り消せない
