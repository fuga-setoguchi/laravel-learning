## 概念

公式ドキュメントによると、Laravel はルートやコントローラーから返されたモデルを、自動で JSON に変換します。このとき、テーブルの列がそのまま JSON に含まれます。

**API リソース**は、モデルと JSON のレスポンスの間に入り、モデルをどんな形の JSON にするかを決めるクラスです。`php artisan make:resource UserResource` で `app/Http/Resources` に作ります。

```php
class UserResource extends JsonResource
{
    public function toArray(Request $request): array
    {
        return [
            'id' => $this->id,
            'name' => $this->name,
            'posts' => PostResource::collection($this->whenLoaded('posts')),
        ];
    }
}
```

コントローラーでは、リソースに包んで返します。

```php
return new UserResource($user);                       // 1件
return UserResource::collection(User::with('posts')->get()); // 一覧
```

モデルの `toResource()` で返すこともできます。公式ドキュメントによると、いちばん外側のリソースは、JSON にするときに `data` というキーで包まれます。

## なぜ必要か

モデルをそのまま返すと、API の形がテーブルの形に縛られます。管理用のフラグや社内向けのメモなど、利用者に見せる必要のない列まで返ります。あとからテーブルに列を足すと、その列も知らないうちに API に出ます。モデルの `#[Hidden]` 属性は隠す列を並べる方式なので、この問題は防げません。

API リソースで返す項目を書いておけば、返すものを自分で決められます。テーブルの列名を変えても、リソースで同じ名前に合わせれば、API の利用者に影響を与えずに済みます（一般的な考え方）。

## どこに書くか

| やりたいこと | 置き場所 |
| --- | --- |
| API で返す項目・名前・形を決める | API リソースの `toArray` |
| どこで JSON にしても出したくない列（パスワードなど）を隠す | モデルの `#[Hidden([...])]` 属性 |
| JSON に含める列だけを決め、ほかはすべて隠す | モデルの `#[Visible([...])]` 属性 |
| リレーションを読み込み済みのときだけ返す | リソースで `$this->whenLoaded('posts')` |
| リレーションを読み込む | コントローラーで `with('posts')` |

`#[Hidden]` と `#[Visible]` は、そのモデルを JSON にするすべての場面で効く設定です。公式ドキュメントによると、`#[Visible]` に並べていない列はすべて隠されます。そのため、列を足したときに知らないうちに出る問題は、`#[Hidden]` では防げず、`#[Visible]` なら防げます。API リソースは、API ごとに返す項目と形を決めるものです。モデルの設定と API リソースは、両方を使えます（使い分けは一般的な考え方）。

リソースの中で `$this->posts` と書くと、読み込まれていないリレーションをその場で問い合わせます。公式ドキュメントは、`whenLoaded` を使うと N+1 問題を避けやすくなると説明しています。

## 良い例と悪い例

悪い例: モデルをそのまま返す。

```php
public function show(User $user)
{
    return response()->json($user);
}
```

なぜ悪いか: 隠す設定をしていない列がすべて返り、内部の情報まで公開されます。

良い例: API リソースで返す項目を決める。

```php
public function show(User $user)
{
    return new UserResource($user);
}
```

## AIが書きがちな誤り

- API のコントローラーで、モデルやコレクションをそのまま返す
- リソースの中で `$this->posts` のようにリレーションを直接読み、一覧で問い合わせを増やす
- リソースの `toArray` で `parent::toArray($request)` を返したままにし、結局すべての列を返す（`make:resource` で作ったひな形の `toArray` がこの形になっている。Laravel 本体のひな形による動き）

API のレスポンスを返すコードを見たら、「返している項目を、だれが決めているか」を確かめましょう。

## まとめ

- モデルをそのまま返すと、隠す設定をしていない列がすべて JSON に含まれる
- API リソースの `toArray` で、返す項目と形を決める
- リレーションは `whenLoaded` で返し、コントローラーで `with` で読み込む
- `#[Hidden]` は全体の安全策、API リソースは API ごとの形を決めるもの
