## 概念

コントローラーから出した処理は、専用のクラスに置きます。よく使われる形が2つあります。どちらも公式ドキュメントの用語ではなく、一般的な設計の考え方です。

| 形 | 中身 | 名前の例 |
| --- | --- | --- |
| Action | 1つのユースケースだけを持つ。公開メソッドは1つ | `PlaceOrder`、`CancelOrder` |
| Service | 関連する複数の処理をまとめる | `PaymentService`（決済・返金） |

```php
// app/Actions/PlaceOrder.php（置き場所も一般的な慣習）
class PlaceOrder
{
    public function __construct(
        private PaymentGateway $gateway,
        private OrderMailer $mailer,
    ) {}

    public function handle(User $user, array $items): Order
    {
        // 金額の計算、保存、在庫の更新、通知 ...
    }
}
```

切り出したクラスは、コントローラーのメソッドの引数で受け取ります。公式ドキュメントのとおり、コントローラーはサービスコンテナが作るので、引数に型を書けば依存が渡されます。

```php
public function store(StoreOrderRequest $request, PlaceOrder $placeOrder)
{
    $order = $placeOrder->handle($request->user(), $request->validated('items'));

    return to_route('orders.show', ['order' => $order]);
}
```

## なぜ必要か

ユースケースごとにクラスがあると、「注文を作る処理はどこか」がファイル名でわかります。コントローラーのほか、Artisan コマンドやキューのジョブからも同じクラスを呼べます。公式ドキュメントによると、ジョブの `handle` メソッドなどもコンテナが依存を渡すので、同じように受け取れます。

テストでは、Action を直接呼んで処理を確かめられます。コントローラーのテストでは、Action をモックに差し替えることもできます（第3章）。

## どこに書くか

Action と Service の選び方は、一般的な考え方です。

| 場面 | 選ぶもの |
| --- | --- |
| 1つの操作の手順をまとめたい | Action（1クラス1ユースケース） |
| 外部サービスとのやり取りなど、関連する処理をまとめたい | Service |

Action のメソッドには、`Request` ではなく、処理に必要な値だけを渡します。`Request` を受け取ると、HTTP のリクエストがない場所から呼べなくなります。同じ理由で、リダイレクトやフラッシュメッセージはコントローラーに残し、Action は結果（作った注文など）を返します。

## 良い例と悪い例

悪い例: Action が Request を受け取り、リダイレクトを返す。

```php
public function handle(Request $request): RedirectResponse
{
    $order = $request->user()->orders()->create([/* ... */]);

    return to_route('orders.show', ['order' => $order]);
}
```

なぜ悪いか: HTTP の処理に縛られ、コマンドやジョブから使えません。

良い例: 必要な値を受け取り、結果を返す（「概念」の `PlaceOrder` を参照）。

## AIが書きがちな誤り

- Action や Service に `Request` を渡し、中で `$request->input()` を読む
- Action の中でリダイレクトやビューを返す
- 切り出したクラスをコントローラーで `new` する、または `static` メソッドにする
- 何でも入る巨大な `OrderService` を作り、メソッドを足し続ける

Action や Service を見つけたら、「HTTP がない場所からも呼べる形か」を確かめましょう。

## まとめ

- Action は1つのユースケース、Service は関連する処理のまとまり（どちらも一般的な考え方）
- 切り出したクラスは、コントローラーの引数で受け取る。コンテナが作って渡す
- Action には Request ではなく必要な値を渡し、結果を返させる
- リダイレクトなどの HTTP の処理はコントローラーに残す
