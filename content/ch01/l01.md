## 概念

フレームワークとは、Webアプリを作るときに毎回必要になる仕組みと、コードの置き場所・書き方の決まり（規約）をまとめて提供する土台です。Laravel は PHP のフレームワークで、リクエストを受け取ってからレスポンスを返すまでの流れ、データベースの操作、画面の表示、セキュリティ対策などを最初から備えています。

自分で書くのは「このアプリならではの処理」だけになり、どのアプリにも共通する部分はフレームワークに任せられます。

## なぜ必要か

フレームワークを使わずに PHP だけで Webアプリを作ると、次のようなものをすべて自分で用意することになります。

- URL ごとにどの処理を呼ぶかを決める仕組み（ルーティング）
- ログイン状態などを保持するセッションの読み書き
- フォームの不正送信を防ぐ CSRF 対策
- データベースへの接続と、SQL の組み立て
- エラーの記録（ログ）と、エラー画面の表示

これらは一度作れば終わりではなく、漏れや誤りがあるとそのまま脆弱性や不具合になります。Laravel では、セッションの読み書きや CSRF トークンの検証が「ミドルウェア」としてすべてのリクエストに一律に適用されます。ページごとに書き忘れる心配がありません。

もう一つの利点が「構造」です。Laravel にはファイルの置き場所や名前の規約があり、コントローラーは `app/Http/Controllers`、画面のテンプレートは `resources/views` に置く、といった形で決まっています。そのため、他の人が書いたコードでも「この処理はここにあるはず」と予測して読めます。

公式ドキュメントは、Laravel の規約と明確な構造が、AIを使った開発に向いているとも述べています。AIが生成したコードを読むときも、規約を知っていれば「Laravelらしいかどうか」を判断できます。この教材の目的である判断力の土台は、規約を知ることです。

一方で、フレームワークを使うことにはトレードオフもあります。規約を学ぶ手間がかかり、規約から外れた書き方をすると利点を失います（これは公式ドキュメントの記載ではなく、一般的な考え方です）。

## 良い例と悪い例

悪い例: フォームの送信を、PHP の機能だけで処理している。

```php
public function store()
{
    if (($_POST['token'] ?? '') !== ($_SESSION['token'] ?? null)) {
        http_response_code(419);
        exit;
    }

    $email = $_POST['email'] ?? '';
}
```

なぜ悪いか: CSRF の検証とセッションを自前で作り直しています。Laravel が全リクエストに適用している検証と二重になるうえ、別のページで同じ処理を書き忘れれば穴になります。`exit` で処理を止めているため、テストからも扱いにくくなります。

良い例: フレームワークの仕組みに任せる。

```php
public function store(Request $request)
{
    $email = $request->input('email');
}
```

CSRF トークンの検証はミドルウェアが行うので、コントローラーには書きません。入力値は `Request` オブジェクトから受け取ります。

## AIが書きがちな誤り

AI は、フレームワークの外の一般的な PHP の知識で書いてしまうことがあります。次のようなコードを見たら、「Laravel が用意している仕組みで置き換えられないか」を疑ってください。

- `$_POST`・`$_GET`・`$_SESSION` を直接読み書きしている
- `header()` や `exit` でレスポンスを返している
- CSRF やセッションの処理をコントローラーの中で書いている

どれも動いてしまうため、見落としやすい誤りです。

見分けるときは、「このコードは、Laravel を使っていない PHP のアプリでもそのまま書けるか」と考えてみてください。そのまま書けるなら、フレームワークの仕組みを使っていない可能性があります。Laravel にはたいてい、同じことをするための仕組み（`Request`、レスポンスを返す `response()`、ミドルウェアなど）が用意されています。

## まとめ

- フレームワークは、共通の仕組みと、コードの構造（規約）を提供する
- セッションや CSRF 対策はミドルウェアが一律に行うため、自前で書かない
- 規約があるので、人もAIも「どこに何があるか」を予測できる
- 規約から外れた書き方は、フレームワークを使う利点を失わせる
