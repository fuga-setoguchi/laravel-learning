## 概念

MVC は、アプリの処理を Model・View・Controller の3つの役割に分ける考え方です。Laravel の公式ドキュメントは、アプリの構造を MVC という枠組みでは説明していません。ここで説明する対応づけは、公式ドキュメントの記載ではなく、一般的な考え方です。ただし、それぞれの部品の役割は、公式ドキュメントの説明に沿っています。

| 役割 | Laravel での部品 | 置き場所 |
| --- | --- | --- |
| Model | Eloquent のモデル | `app/Models` |
| View | Blade テンプレート | `resources/views` |
| Controller | コントローラー | `app/Http/Controllers` |

- **モデル**: Eloquent は、データベースを扱うための ORM です。1つのテーブルに1つのモデルが対応し、モデルを通してテーブルを読み書きします。規約では、`Book` モデルは `books` テーブルに対応します
- **ビュー**: コントローラーやアプリのロジックと、表示のロジックを分けるものです。Blade という書き方で、`.blade.php` の拡張子のファイルに書きます
- **コントローラー**: 関連するリクエストの処理を1つのクラスにまとめます。たとえば `BookController` が本に関するリクエストを担当します

## なぜ必要か

役割を分けておくと、変更の影響範囲が小さくなります。一覧の見た目を変えたいときはビューだけ、「公開済みの本だけを出す」という条件を変えたいときはデータを取り出す部分だけを直せば済みます。

すべてを1か所に書くと、見た目を少し変えるだけでもデータの取り出し方まで読み解く必要があり、思わぬところを壊しやすくなります。役割ごとに分かれていれば、テストも役割ごとに書けます。

## どこに書くか

- テーブルの読み書きと、そのデータの性質（どの列を一括代入してよいか、どのテーブルとつながるか）はモデル
- HTML の構造と、データをどう見せるかはビュー
- リクエストを受け取り、データを集めてビューに渡すのはコントローラー

コントローラーには「つなぐ」処理だけを書き、HTMLの組み立てや細かいデータの加工は置かないのが基本です。コントローラーを太らせない設計は、第5章で詳しく扱います。

## 良い例と悪い例

悪い例: コントローラーでSQLを書き、HTMLも組み立てている。

```php
public function index()
{
    $books = DB::select('select * from books where published = true');

    $html = '<ul>';
    foreach ($books as $book) {
        $html .= '<li>' . $book->title . '</li>';
    }

    return $html . '</ul>';
}
```

なぜ悪いか: 表示の変更でもコントローラーを直すことになります。さらに、タイトルをそのまま連結しているため、`<script>` などが含まれていると、そのままHTMLとして実行されてしまいます（XSS）。

良い例: データはモデルから取り出し、表示はビューに任せる。

```php
public function index()
{
    return view('books.index', [
        'books' => Book::where('published', true)->get(),
    ]);
}
```

```blade
<ul>
    @foreach ($books as $book)
        <li>{{ $book->title }}</li>
    @endforeach
</ul>
```

Blade の `{{ }}` は値を自動でエスケープするので、XSS も防げます。

## AIが書きがちな誤り

- コントローラーの中で文字列としてHTMLを組み立てて返す
- モデルに「HTMLを返すメソッド」を作り、表示の責務をモデルに持たせる
- Blade で `{!! !!}` を使い、エスケープを外してしまう

どれも画面は正しく表示されるため、見た目だけでは気づけません。「この処理は、どの役割のものか」を確かめる習慣をつけましょう。

## まとめ

- MVC は Model・View・Controller に役割を分ける考え方（公式ドキュメントは MVC の枠組みでは説明していない）
- Laravel では、モデルは app/Models、ビューは resources/views、コントローラーは app/Http/Controllers
- ビューは表示のロジックをアプリのロジックから分ける。Blade の {{ }} は自動でエスケープする
- コントローラーは、リクエストとモデルとビューをつなぐ役割に絞る
