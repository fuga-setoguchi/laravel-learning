## 概念

第7章でトランザクションを、この章でキューを扱いました。このレッスンでは、2つを組み合わせたときの問題を扱います。

トランザクションの中でジョブをキューに入れると、**トランザクションが確定する前に、ワーカーがジョブを実行する**ことがあります。ワーカーは別のプロセスで、データベースにも別の接続でつなぐので、確定していない書き込みは見えません（データベースの一般的な動き）。公式ドキュメントも、確定前にジョブが実行されると、トランザクションの中で作ったレコードがまだデータベースにないことがある、と説明しています。

```php
DB::transaction(function () use ($user, $data) {
    $order = $user->orders()->create($data);

    SendOrderConfirmation::dispatch($order);   // 確定前に実行されることがある
});
```

## なぜ必要か

この問題は、2つの形で表れます。

- **レコードが見つからない**: ジョブは注文の id から取り出し直そうとしますが、確定前なので見つからず、失敗します
- **ロールバックしたのに実行される**: トランザクションが途中で失敗してロールバックされても、キューに入ったジョブは残り、存在しない注文の確認メールが送られます

ワーカーの速さや負荷によって起きたり起きなかったりするので、開発中には気づきにくい不具合です。

## どこに書くか

公式ドキュメントには、確定を待ってからキューに入れる方法がいくつか書かれています。

| やりたいこと | 書き方 |
| --- | --- |
| 1つのジョブだけ確定後に入れる | `SendOrderConfirmation::dispatch($order)->afterCommit()` |
| その接続のジョブをすべて確定後に入れる | `config/queue.php` の接続で `'after_commit' => true` |
| 設定が true のとき、1つだけすぐ入れる | `->beforeCommit()` |
| キューで実行するリスナーを確定後に | リスナーに `ShouldQueueAfterCommit` を実装 |
| イベントそのものを確定後に発行 | イベントに `ShouldDispatchAfterCommit` を実装 |

公式ドキュメントによると、`after_commit` を true にすると、開いているトランザクションがすべて確定してからジョブがキューに入ります。トランザクションが開いていなければ、すぐに入ります。ロールバックされたトランザクションの中で入れたジョブは捨てられます。キューに入るリスナー・メール・通知も、同じように確定を待ちます。

このアプリのような新しいアプリの `config/queue.php` では、`after_commit` は `false` です（Laravel 本体のひな形による設定）。トランザクションの中でジョブを入れるときは、`afterCommit()` を付けるか、設定を変えます。

## 良い例と悪い例

悪い例: 遅らせて、確定を待ったつもりになる。

```php
SendOrderConfirmation::dispatch($order)->delay(now()->addSeconds(5));
```

なぜ悪いか: 確定が遅れれば同じ問題が起き、ロールバックされてもジョブは実行されます。

良い例: 確定してからキューに入れる。

```php
DB::transaction(function () use ($user, $data) {
    $order = $user->orders()->create($data);

    SendOrderConfirmation::dispatch($order)->afterCommit();
});
```

## AIが書きがちな誤り

- トランザクションの中で、`afterCommit()` を付けずにジョブを入れる
- 確定を待つために、`delay` で数秒遅らせる
- イベントを発行し、キューで実行するリスナーが確定前に動くことに気づかない
- 「開発中は動いた」ことを理由に、確定前に実行される問題を見落とす

トランザクションの中の `dispatch` を見たら、「このジョブが確定前に、あるいはロールバックの後に動いたらどうなるか」を考えましょう。

## まとめ

- トランザクションの中で入れたジョブは、確定前に実行されることがある
- 確定前のレコードは見えず、ロールバックしてもジョブは残る
- `afterCommit()` や `after_commit` の設定で、確定後にキューに入れる
- リスナーは `ShouldQueueAfterCommit`、イベントは `ShouldDispatchAfterCommit`
