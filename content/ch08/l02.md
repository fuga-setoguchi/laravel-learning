## 概念

**認証**（authentication）は、「リクエストしてきたのは誰か」を確かめることです。ログインフォームでメールアドレスとパスワードを照合し、以降のリクエストではセッションでそのユーザーだと確かめます。

**認可**（authorization）は、「その人が、その操作をしてよいか」を決めることです。「記事を編集できるのは作成者だけ」「管理画面を見られるのは管理者だけ」といった判断です。

公式ドキュメントも、ユーザーを認証する機能とは別に、操作を許すかどうかを決める認可の機能を用意していると説明しています。認証で「誰か」がわかってから、認可で「許すか」を決める、という順番になります。

```php
$user = $request->user();          // 認証: 誰か（ログインしていなければ null）

$user->id === $post->user_id;      // 認可: この記事を操作してよいか
```

## なぜ必要か

2つを混同すると、「ログインしていれば何でもできる」アプリになります。ルートに `auth` ミドルウェアを付けて安心しても、ログインしているユーザーなら誰でも、他人の記事を編集・削除できてしまいます。

AIに「認可を追加して」と頼んでも、ログインしているかの確認だけが足されることがあります。どちらの確認なのかを見分けられないと、レビューで見落とします。

たとえば、記事の投稿サービスで考えます。

- 記事の一覧を見る: 誰でもよい（認証も認可もいらない）
- 記事を書く: ログインしていればよい（認証だけ）
- 記事を編集・削除する: ログインしていて、かつ、その記事の作成者である（認証と認可）

操作ごとに「誰か」を知る必要があるか、「その人に許すか」まで決める必要があるかを分けて考えると、どこに何を書くべきかが見えてきます（一般的な考え方）。

## どこに書くか

| 確かめること | Laravel での書き方 | 失敗したとき |
| --- | --- | --- |
| 認証（ログインしているか） | ルートに `->middleware('auth')` | ログイン画面へリダイレクト |
| 認可（操作してよいか） | Gate や Policy（この章で扱う） | 403 |

公式ドキュメントによると、`auth` ミドルウェアは、認証されていないユーザーをログイン画面にリダイレクトします。Laravel 本体の実装では、JSON を求めるリクエストには、リダイレクトの代わりに 401 を返します。認可に失敗したときは、403 になると公式ドキュメントに書かれています。

認証のあとに認可を書く、という順番も大切です。認可は「誰か」がわかっていないと判断できないからです。ログインしたユーザーは、コントローラーで `$request->user()` や `Auth::user()` で取り出せます。

認可漏れによる具体的な脆弱性は、第11章で扱います。

## 良い例と悪い例

悪い例: ログインしているかだけで、編集を許す。

```php
Route::put('/posts/{post}', [PostController::class, 'update'])
    ->middleware('auth');
// コントローラーでは何も確かめずに更新する
```

なぜ悪いか: ログインしているユーザーなら誰でも、他人の記事を更新できます。

良い例: 認証はミドルウェアで、認可は Policy で確かめる。

```php
Route::put('/posts/{post}', [PostController::class, 'update'])
    ->middleware('auth')
    ->can('update', 'post');
```

`->can('update', 'post')` は、PostPolicy の `update` を使って、ルートの記事を更新してよいかを確かめます（Policy はこの章の4つ目、確かめる場所は5つ目のレッスンで扱います）。

## AIが書きがちな誤り

- 「認可を追加して」に対して、`Auth::check()` や `auth` ミドルウェアだけを足す
- `auth` ミドルウェアを付けたことで、他人のデータへの操作も防げていると考える
- 認可の失敗に 401 を返し、認証の失敗と区別しない

認可を書いたと言われたら、「ログインしているか」ではなく「このユーザーが、この対象を操作してよいか」を確かめているかを見ましょう。

## まとめ

- 認証は「誰か」、認可は「その操作をしてよいか」
- `auth` ミドルウェアは、ログインしているかしか確かめない
- 認証に失敗するとログイン画面へ、認可に失敗すると 403
- 認証で誰かがわかってから、認可で判断する
