## 概念

Policy に書いた認可は、いくつかの場所から確かめられます。

| 確かめる場所 | 書き方 |
| --- | --- |
| ルート（ミドルウェア） | `->can('update', 'post')` |
| コントローラー | `Gate::authorize('update', $post)` |
| FormRequest | `authorize` で `$this->user()->can('update', $this->post)` |
| ユーザーのモデル | `$request->user()->can('update', $post)` |
| Blade | `@can('update', $post)` |

公式ドキュメントによると、`Gate::authorize` は拒否されると `AuthorizationException` を投げ、Laravel が自動で 403 のレスポンスに変えます。ルートの `->can(...)` も、拒否されると 403 になります。FormRequest の `authorize` が `false` を返したときも 403 になり、コントローラーは実行されません。

## なぜ必要か

確かめる場所を取り違えると、認可したつもりでも守れていないことがあります。代表は、Blade の `@can` でボタンを隠しただけのコードです。`@can` は表示を変えるだけなので、リクエストを直接送れば、コントローラーはそのまま実行されます。

確かめる順番も大切です。データを書き換えた後に認可を確かめても、403 を返したときには、データはすでに変わっています。

## どこに書くか

選び方は、一般的な考え方です。

| 場面 | 確かめる場所 |
| --- | --- |
| ルートのモデルについて、操作の前に確かめるだけでよい | ルートの `->can('update', 'post')` |
| その操作の入力を FormRequest で検証している | FormRequest の `authorize` |
| 処理の途中の値で判断する、ルートでは書きにくい | コントローラーの最初で `Gate::authorize` |
| 画面の表示を変える | Blade の `@can`（処理する側の認可と必ず組み合わせる） |

コントローラーの属性を使う場合は、メソッドに `#[Authorize('update', 'post')]` を付けて、ミドルウェアと同じ確認をすることもできます（公式ドキュメントに記載）。

どこで確かめるにしても、データを書き換える前に確かめます。1つの操作の中で、確かめる場所を複数に散らさず、どこで確かめているかがわかるようにします（一般的な考え方）。FormRequest の `authorize` を使わないなら、`true` を返すようにすることは第5章で扱いました。

Laravel 13.x の新しいアプリでは、`app/Http/Controllers/Controller.php` は空のクラスです（Laravel 本体のひな形による動き）。古い書き方の `$this->authorize()` は、そのままでは使えません。公式ドキュメントのとおり、`Gate::authorize()` を使います。

## 良い例と悪い例

悪い例: 書き換えた後に確かめる。

```php
public function destroy(Post $post)
{
    $post->delete();
    Gate::authorize('delete', $post);
    // ...
}
```

なぜ悪いか: 拒否されて 403 が返っても、記事はすでに消えています。

良い例: ルートで、処理の前に確かめる。

```php
Route::delete('/posts/{post}', [PostController::class, 'destroy'])
    ->can('delete', 'post');
```

## AIが書きがちな誤り

- Blade の `@can` でボタンを隠すだけで、ルートやコントローラーで確かめない
- データを書き換えた後に `Gate::authorize` を呼ぶ
- 空の `Controller` を継承しているのに、`$this->authorize()` を使う
- 同じ操作の認可を、ルートとコントローラーと FormRequest に重ねて書き、どれが効いているかわからなくする

認可のコードを見たら、「処理する側で確かめているか」「書き換えの前か」を確かめましょう。

## まとめ

- Blade の `@can` は表示を変えるだけ。処理する側で必ず確かめる
- ルートの `->can`、コントローラーの `Gate::authorize`、FormRequest の `authorize` は、拒否されると 403
- 認可は、データを書き換える前に確かめる
- 新しいアプリでは `$this->authorize()` ではなく `Gate::authorize()` を使う
