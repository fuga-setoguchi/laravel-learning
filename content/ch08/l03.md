## 概念

Laravel の認証は、2つの部品で動きます。公式ドキュメントによると、**ガード**はリクエストごとにユーザーをどう認証するか（セッションなど）を決め、**プロバイダー**はユーザーを保存先（データベースなど）からどう取り出すかを決めます。

ログインや会員登録の画面と処理は、自分で一から書かずに、**スターターキット**から始めます。公式ドキュメントによると、スターターキットには、ユーザーの登録と認証に必要なルート・コントローラー・ビューが含まれていて、認証の処理には Laravel Fortify が使われています。

パスワードは、**ハッシュ**にして保存します。ハッシュは、元のパスワードに戻せない値です。

```php
$user->password = Hash::make($request->input('password'));

Hash::check($plain, $user->password);   // 照合
```

## なぜ必要か

ログインの処理は、短く見えて、漏れると危ない点が多くあります。パスワードの照合、ログイン後のセッションの再生成、試行回数の制限、パスワードの再設定です。公式ドキュメントによると、ログインに成功したらセッションを再生成して、セッション固定攻撃を防ぎます。スターターキットや Fortify を使えば、ログインのときにセッションの ID が自動で再生成されます。自分でログインの処理を書くなら、`$request->session()->regenerate()` を自分で呼ぶ必要があります。

公式ドキュメントによると、スターターキットでは、ログインの試行にも自動でレート制限が付きます。制限は、メールアドレス（ユーザー名）と IP アドレスの組み合わせごとに数えます。第4章のレート制限で扱った、組み合わせで数える考え方と同じです。自前で書くと、こうした点を1つずつ自分で実装し、漏れなく保つ必要があります。

パスワードをそのまま保存すると、データベースが漏れた時点で、すべてのパスワードが使われます。同じパスワードを別のサービスに使っている利用者も多いので、被害はアプリの外にも広がります（一般的な考え方）。

## どこに書くか

| やりたいこと | 書き方 |
| --- | --- |
| ログイン・登録の画面と処理 | スターターキット（Fortify が処理を持つ） |
| パスワードを保存する | `Hash::make($password)` |
| ログインで照合する | `Auth::attempt(['email' => ..., 'password' => ...])` |
| パスワードを照合する（ログイン以外） | `Hash::check($plain, $hashed)` |

公式ドキュメントによると、`Hash` は bcrypt と Argon2 を使え、新しいアプリの既定は bcrypt です。どちらも計算の重さ（work factor）を調整でき、パスワードのハッシュは遅いほうがよい、とされています。漏れたハッシュから総当たりで探すのに、時間がかかるからです。あとで work factor を上げたときは、ログインのときに古いハッシュが自動で作り直されます（公式ドキュメントに記載）。

`Auth::attempt` には、入力されたパスワードをそのまま渡します。公式ドキュメントによると、Laravel がハッシュと照合するので、自分でハッシュにしてはいけません。

暗号化（`Crypt`）は、鍵があれば元に戻せます。パスワードは照合さえできればよく、元に戻す必要がないので、ハッシュを使います（一般的な考え方）。

## 良い例と悪い例

悪い例: ハッシュを作り直して、データベースで比べる。

```php
$user = User::where('email', $email)
    ->where('password', Hash::make($password))
    ->first();
```

なぜ悪いか: bcrypt などは、ハッシュを作るたびにランダムなソルトを混ぜるので、毎回違う値になります（公式ドキュメントの記載ではなく、一般的な知識）。正しいパスワードでも一致しません。

良い例: 照合は `Auth::attempt` に任せる。

```php
if (Auth::attempt($request->only('email', 'password'))) {
    $request->session()->regenerate();

    return redirect()->intended('dashboard');
}
```

## AIが書きがちな誤り

- ログインや登録の処理を、スターターキットを使わずに一から書く
- パスワードを `Crypt` で暗号化して保存する
- `Hash::make` で作り直したハッシュと、保存した値を `===` や `where` で比べる
- `Auth::attempt` に、ハッシュにしたパスワードを渡す
- ログインに成功した後、セッションを再生成しない

パスワードを扱うコードを見たら、「保存はハッシュか」「照合は `Auth::attempt` か `Hash::check` か」を確かめましょう。

## まとめ

- ログインや登録は、スターターキット（Fortify）から始める
- パスワードは暗号化ではなく、元に戻せないハッシュで保存する
- ハッシュは作るたびに値が変わるので、照合は `Auth::attempt` や `Hash::check` で
- ログインに成功したら、セッションを再生成する
