## 概念

データベースから取り出す量は、そのまま時間とメモリになります。`all()` や `get()` は、条件に合うすべての行の全列をモデルにして、一度にメモリに載せます。公式ドキュメントも、数万件の Eloquent のレコードを読み込もうとすると、メモリが足りなくなることがあると書いています。

大量のデータを扱うときは、次の2つを考えます。

- **分けて取り出す**: `chunk`・`chunkById`・`lazy` で、少しずつ取り出して処理する
- **必要なものだけ取り出す**: 必要な列だけを `select` する。件数や有無は、データベースに数えさせる

```php
User::where('subscribed', true)->chunkById(500, function ($users) {
    foreach ($users as $user) {
        // 500人ずつ処理する
    }
});
```

## なぜ必要か

開発中のデータが数十件だと、`all()` で取り出しても問題は見えません。本番で行が増えると、コマンドがメモリ不足で止まったり、画面がいつまでも返らなかったりします（一般的な考え方）。

公式ドキュメントによると、`chunk` は今の区切りのモデルだけを取り出すので、メモリの使用量を大きく減らせます。ただし、取り出しながら、取り出す条件に関わる列を更新すると、区切りがずれて思いどおりの結果にならないことがあります。そのときは、前の区切りの最後の id より大きい行を取り出す `chunkById` を使います。

公式ドキュメントによると、`chunkById` と `lazyById` は、id で区切るための where の条件を自分で足します。そのため、自分の条件に `orWhere` を使うときは、`where(function ($query) { ... })` のようにクロージャでまとめます（OR とクロージャの関係は第6章のスコープのレッスンで扱いました）。

画面に一覧を出すなら、`paginate` で1ページ分だけを取り出します。`chunk` や `lazy` は、Artisan コマンドやジョブで全件を処理するときに使うもので、画面の一覧に使うものではありません（一般的な考え方）。公式ドキュメントによると、`lazy` は裏で分けてクエリを実行しながら、1つにつながった LazyCollection を返すので、`foreach` でそのまま回せます。

## どこに書くか

| やりたいこと | 書き方 |
| --- | --- |
| 決まった件数ずつ処理する | `chunk(500, ...)`、更新しながらなら `chunkById` |
| 1件ずつ流れるように処理する | `lazy()`、更新しながらなら `lazyById()` |
| 必要な列だけ取り出す | `select('id', 'email')`、1列なら `pluck('title')` |
| 件数を知る | `count()` |
| あるかどうかを知る | `exists()` |

公式ドキュメントによると、`cursor` はクエリを1回だけ実行し、メモリに置くモデルを1件にしますが、リレーションの Eager Loading ができません。PDO が結果をためるので、いずれメモリが足りなくなることもあり、その場合は `lazy` を検討するよう書かれています。

`count` や `max` などの集計は、データベースが計算するので、`get()` で取り出してから PHP で数えるより速く済みます。関連するモデルの件数は、モデルを読み込まずに数える `withCount` を使います（第7章）。

## 良い例と悪い例

悪い例: 全件を取り出してから数える、絞り込む。

```php
$count = Post::all()->where('status', 'published')->count();
```

なぜ悪いか: すべての記事をモデルにしてから PHP で絞り込むので、行が増えるほど遅く、メモリも使います。

良い例: データベースに絞り込ませ、数えさせる。

```php
$count = Post::where('status', 'published')->count();
```

## AIが書きがちな誤り

- 大量の行を `all()` や `get()` で取り出してから、`foreach` で回す
- 取り出す条件の列を更新しながら、`chunk` を使う
- `chunkById` の前の条件に `orWhere` を使うのに、クロージャでまとめない
- あるかどうかを、`get()->count() > 0` で確かめる
- 1列だけ使うのに、全列を取り出す

クエリを見たら、「本番の件数でも、この量を取り出して大丈夫か」「数える・絞り込むのは、データベースに任せられないか」を確かめましょう。

## まとめ

- `all()`・`get()` は全件を一度にメモリに載せる。大量なら `chunk` や `lazy` で分ける
- 取り出しながら条件の列を更新するなら、`chunkById`・`lazyById` を使う
- 必要な列だけを取り出し、件数は `count()`、有無は `exists()` で確かめる
- 絞り込み・数えることは、PHP ではなくデータベースに任せる
