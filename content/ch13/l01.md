## 概念

**キャッシュ**は、時間のかかる処理の結果を、しばらく取っておいて使い回す仕組みです。公式ドキュメントも、データを取り出す処理の中には、CPU を多く使ったり数秒かかったりするものがあり、その結果をキャッシュに入れておけば、次からは速く取り出せると説明しています。

```php
$posts = Cache::remember('popular_posts', 600, function () {
    return Post::withCount('likes')->orderByDesc('likes_count')->take(10)->get();
});
```

公式ドキュメントによると、`remember` は、キャッシュに値があればそれを返し、なければクロージャを実行して、その結果をキャッシュに入れます。2つ目の引数は、キャッシュに入れておく秒数です。

## なぜ必要か

同じ集計を、一覧を開かれるたびに何度も計算するのはむだです。キャッシュすれば、データベースへの問い合わせや外部の API の呼び出しを減らし、画面を速く返せます。

ただし、キャッシュには必ず**古いデータを見せる危険**があります。キャッシュはデータベースの変更を見張っていないので、記事を削除しても、キャッシュが残っている間は、削除した記事が表示されます。値段・在庫・権限のように、少しでも古いと困るデータをキャッシュすると、間違った値段で売ったり、権限を外した人に見せ続けたりします（一般的な考え方）。

キャッシュを足す前に、本当に遅い原因がどこかを確かめます。N+1 問題（第7章）や、インデックスのない検索（次のレッスン）が原因なら、キャッシュで隠すより、クエリを直すほうが先です。キャッシュは、遅い処理を直したうえで、それでも時間がかかるものに使います（一般的な考え方）。

## どこに書くか

キャッシュに向くかどうかは、一般的な考え方で判断します。

| 向く | 向かない |
| --- | --- |
| よく読まれるが、あまり変わらない | 頻繁に変わる |
| 作るのに時間がかかる（集計、外部の API） | すぐに取り出せる |
| 少し古くても困らない | 古いと困る（在庫、権限、値段） |

古いデータを減らすには、次の2つを組み合わせます。

| 方法 | 書き方 |
| --- | --- |
| 期限を決めて入れる | `Cache::remember('key', 600, ...)`、`Cache::put('key', $value, 600)` |
| 元のデータを変えたときに消す | `Cache::forget('key')` |

公式ドキュメントによると、`put` に期限を渡さないと、値は期限なしで入ります。`Cache::flush()` は、キャッシュ全体を消します。設定したキャッシュの接頭辞も考慮しません（Laravel 本体の実装による動き）。1つのキーを消すときは `forget` を使います。同じキャッシュのストア（Redis など）をほかのアプリと共有していると、そのアプリの値まで消えます（一般的な考え方）。少し古い値を返しながら裏で作り直す `Cache::flexible` もあります。

ユーザーごとに違うデータをキャッシュするときは、キーにユーザーの id を含めます。全員で同じキーを使うと、ほかの人のデータが表示されます（一般的な考え方）。

## 良い例と悪い例

悪い例: 期限なしで入れ、更新しても消さない。

```php
Cache::rememberForever('posts.index', fn () => Post::latest()->take(20)->get());
```

なぜ悪いか: 記事を編集・削除しても、古い一覧が返り続けます。

良い例: 期限を決めて入れ、更新したら消す。

```php
$posts = Cache::remember('posts.index', 600, fn () => Post::latest()->take(20)->get());

// 更新・削除の後
Cache::forget('posts.index');
```

## AIが書きがちな誤り

- ユーザーごとに違うデータを、全員で同じキーにキャッシュする
- 期限なしでキャッシュし、元のデータを変えても消さない
- 在庫や権限のように、古いと困るデータをキャッシュする
- 1つのキーを消したいのに、`Cache::flush()` ですべてを消す

キャッシュを見たら、「このデータが古くなったら、誰が何に困るか」「キーは、見せる相手ごとに分かれているか」を確かめましょう。

## まとめ

- キャッシュは、よく読まれ、あまり変わらず、作るのに時間がかかるデータに使う
- `remember` は、なければ作って入れ、あれば返す
- 古いデータを見せる危険があるので、期限を決め、元のデータを変えたら `forget` で消す
- ユーザーごとのデータは、キーにユーザーの id を含める
